# 共享设计原则 (Shared Design Principles)

所有技能遵循以下设计原则：

---

## 1. 优先使用一手来源

规则基于官方文档、已发布标准、或明确的本地来源，不是泛泛的审美偏好。

- 公文写作 → GB/T 9704-2012 原文
- Python 开发 → 官方 PEP 8 / pyproject.toml 规范
- 专利写作 → 中国专利法原文
- 学术写作 → 目标期刊/会议的投稿指南

## 2. 显式胜过隐式

每条规则说明理由，而非只给断言。

```
❌ "使用 MIT 许可证"
✓ "使用 MIT 许可证 — 这是本 repo 的既有许可证，且 MIT 允许商业使用和重新许可，兼容性最广"
```

## 3. 上下文感知

技能的指令和工作流必须感知任务上下文。

- 学术写作：摘要/引言/方法/讨论使用不同逻辑
- 架构设计：阶段1-6各有独立的质量门和退出条件
- 检查/审查：Issue vs PR 使用不同的分析模板

## 4. 输出优先

每个技能返回可直接使用的产物。

- 学术写作 → 可粘贴的 LaTeX/Markdown 文本
- 架构设计 → 架构图、模块分解表、任务清单
- 公文写作 → 符合 GB/T 9704-2012 格式的 docx/md 输出
- 审查/检查 → 结构化报告含 permalink 证据

## 5. 可扩展

每个技能自包含在自己的目录中。新增技能不要求修改既有技能。

- 共享内容通过 `_shared/` 层解耦
- 技能间通过命令引用集成（如 `/skill <name>`），不通过代码依赖
- manifest.yaml 声明技能自身的轴和片段，不影响其他技能

## 6. 上下文经济

SKILL.md 应精简。具体内容按需加载，避免每次调用都加载全量规则。

- Router 风格的 SKILL.md 只包含路由协议（50-80行）
- 通过 manifest.yaml 声明 axes，按需加载 fragments
- 深层参考放在 `references/` 或 `rules/` 中，按条件加载
- 共享内容放在 `_shared/` 中，避免跨技能重复

## 7. 安全第一

所有涉及 bash 执行的技能必须遵循 `_shared/core/safety-rules.md`。

- 超时保护、范围限制、交互禁用
- 无限循环必须有预算上限
- 不执行未检查的网络脚本
