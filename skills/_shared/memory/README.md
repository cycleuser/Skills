# Shared Memory System

Per-skill persistent storage for opencode skills. Each skill gets a namespaced key-value store with atomic JSON writes. Zero dependencies, Python stdlib only.

## Quick Start

```bash
# Write (from stdin)
echo '"value"' | python _shared/memory/cli.py set <skill> <key>

# Write structured data
echo '{"ch": 15, "words": 45000}' | python _shared/memory/cli.py set literary-ghostwriter progress

# Write a simple string
python _shared/memory/cli.py set brief-write tone --string casual

# Read
python _shared/memory/cli.py get <skill> <key>
# => the stored JSON value, or "null" if missing

# Check existence (exit code 0/1)
python _shared/memory/cli.py has <skill> <key> && echo "exists"

# List all keys
python _shared/memory/cli.py list <skill>

# Delete
python _shared/memory/cli.py delete <skill> <key>

# Export all data
python _shared/memory/cli.py export <skill>
```

## How It Works

```
_shared/memory/
├── cli.py                    # CLI tool (this file is the API)
├── README.md                 # This document
└── <skill-name>/             # Per-skill namespace (auto-created)
    └── data/
        ├── key1.json          # { "_meta": {...}, "value": ... }
        └── key2.json
```

- **Namespaced**: Each skill reads/writes only its own directory. Skill A cannot access skill B's data.
- **Atomic writes**: Uses temp-file + `os.replace()` — no partial writes on crash.
- **Schema-free**: Any JSON-serializable value is accepted. Strings, numbers, objects, arrays.
- **Self-describing**: Each `.json` file has a `_meta` wrapper with `skill`, `key`, `created`, `updated`.

## When to Use

Use shared memory for data that **persists across opencode sessions**:

| Scenario | Key | Value |
|----------|-----|-------|
| Novel project state | `current_project` | `"长安雪"` |
| Chapter progress | `progress` | `{"ch": 15, "words": 45000}` |
| User style prefs | `preferred_authors` | `["鲁迅", "金庸"]` |
| Scan results | `last_scan` | `{"date": "...", "files": 12, "risks": 3}` |
| Iteration state | `iteration` | `{"goal": "...", "loop": 5, "pct": 73}` |

## When NOT to Use

- **One-session temp data** — use the LLM's context window, not disk.
- **Large files** (>100KB) — use the skill's own `projects/` or workspace directory.
- **Secrets/tokens** — store in environment variables or macOS keychain, never here.

## Integration Pattern

Add this section to a skill's SKILL.md:

```markdown
## Shared Memory

This skill persists state via the shared memory system. See `../_shared/memory/README.md` for full API.

**Stored keys**: `current_project`, `progress`, `preferred_authors`

Usage from this skill's directory:
\`\`\`bash
# Read state on skill load
python ../_shared/memory/cli.py get literary-ghostwriter current_project

# Save state after user action
echo '{"ch": 16, "words": 48000}' | python ../_shared/memory/cli.py set literary-ghostwriter progress
\`\`\`
```

## Direct File Access

The CLI can also be bypassed — the LLM can read/write `.json` files directly with opencode's file tools:

```
_shared/memory/<skill>/data/<key>.json
```

Each file format:
```json
{
  "_meta": {
    "skill": "literary-ghostwriter",
    "key": "progress",
    "created": "2026-07-14T04:45:56",
    "updated": "2026-07-14T04:45:56"
  },
  "value": { "ch": 15, "words": 45000 }
}
```

The `value` field holds whatever JSON the skill stored. The `_meta` wrapper is auto-generated by `set`.

## Design Principles

1. **Zero dependencies** — stdlib-only Python. Skills never need to install packages.
2. **Minimal boilerplate** — One bash call per operation. No imports, no setup code.
3. **Compatible** — Existing skills keep working unchanged. New skills opt in by calling the CLI.
4. **Elegant** — The CLI doubles as documentation. `cli.py --help` explains everything.
5. **Safe** — Atomic writes, sanitized paths, per-skill isolation. No race conditions.
