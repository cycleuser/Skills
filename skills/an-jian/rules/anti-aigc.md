# 流程文档反AIGC检测规则

同 he-bing/rules/anti-aigc.md 的流程文档反AIGC规则。

安全审计报告补充特有规则：

## 安全审计特有AIGC模式

### 风险等级无依据

```
❌ AI模式：
"此风险等级为高"
"建议修复"

✅ 专业写法：
"风险等级：HIGH。依据：curl|bash 模式可在任意目标主机执行代码，影响范围100%用户（未安装前），CVSS评分9.8。修复方案：下载脚本到/tmp后用less查看再执行，修改后CVE编号待定。"
```

### 修复建议笼统

```
❌ AI模式：
"建议修复此安全问题"
"建议移除危险代码"

✅ 专业写法：
"修复方案：将 quick-install.sh 中第3行：
  curl -fsSL $URL | bash
改为：
  curl -fsSL $URL -o /tmp/install.sh && less /tmp/install.sh && bash /tmp/install.sh
此修改保留功能但增加人工审查环节。"
```

### 发现列表无具体位置

```
❌ AI模式：
"发现3处安全问题"
"存在代码注入风险"

✅ 专业写法：
"问题1（高危）：quick-install.sh:3 — curl|bash 管道执行，攻击者可控$URL即RCE
 问题2（中危）：install.sh:47 — 硬编码 /tmp 路径，symbolic link attack
 问题3（低危）：README.md:12 — 版本号未与实际发布tag同步"
```

### 审计结论空洞

```
❌ AI模式：
"总体安全状况良好，建议继续改进"
"安全水平处于可接受范围"

✅ 专业写法：
"审计结论：3项发现（高1/中1/低1），高危项为 quick-install.sh:3 的RCE（CVSS 9.8），需立即修复。修复后整体风险降为低。截止建议：2026-06-16前完成高危项修复。"
```

## 核心原则

1. **发现必有位置**：每个安全问题标注 文件:行号
2. **风险必有依据**：每个风险等级标注 CVSS评分 + 具体攻击路径
3. **修复必可操作**：每个修复建议含具体代码变更diff或操作步骤
4. **结论必可量化**：审计结论含 发现数/高/中/低分布 + 截止时间

## 安全审计高发AIGC模式检测清单

- [ ] 风险等级是否都有CVSS评分和攻击路径？
- [ ] 每个发现是否标注了文件:行号？
- [ ] 修复建议是否包含具体的代码变更？
- [ ] 审计结论是否包含量化统计和截止时间？
- [ ] 是否避免了"总体安全状况良好"等空洞结论？
- [ ] 是否避免了"建议修复"等无操作性的建议？
- [ ] 是否避免了纯列表式发现描述（没有位置和依据）？

## AIGC率评分标准

| AIGC率 | 等级 | 说明 |
|--------|------|------|
| 0-15% | 专业级 | 发现精确到行号，CVSS评分完整，修复方案有diff |
| 16-30% | 可接受 | 位置标注基本完整，但部分描述缺少攻击路径 |
| 31-50% | 需修改 | 发现笼统无位置，或修复建议不可操作 |
| 51-70% | 需重写 | 大量空洞结论，风险等级无依据 |
| 71-100% | 纯AI模板 | "总体安全状况良好"+"建议修复"式套话 |
