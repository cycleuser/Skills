# 防丢失协议 (No-Loss Protocol)

批处理最容易出事故的就是删错/覆盖错。以下为硬约束。

## 顺序铁律

```
新文件全部生成 → 逐个可打开性校验 → 内容抽样核对
→ 确认无误 → 才允许删旧文件/覆盖原文件
```

## 具体规则

1. **旋转/转换**：输出到新名（`rotated_`/`converted_` 前缀或新目录），先不动原文件。
2. **重命名**：`os.rename` 前先确认目标不存在；映射表先给用户确认。
3. **删除旧文件**：仅在本批次新文件全部通过校验后执行；`rm` 用变量守卫逐项删，禁 `rm -rf`。
4. **大改动前备份**：批次文件多时，先 `tar -czf` 或统一改 `.bak` 后缀。
5. **中途失败**：立即停止并报告，不继续后续步骤（避免半成品状态）。

## 校验项（删除旧文件前必须全绿）

- [ ] 每个新文件能被对应库打开（`Image.open`/`fitz.open`/`Document`）
- [ ] 内容抽样核对（OCR/文本）与预期一致
- [ ] 新文件数量 == 预期数量
- [ ] 命名符合规范
