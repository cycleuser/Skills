# Deepwork Protocol

高风险多阶段编码工作流协议。仅当工作明显大或高风险时启用:多依赖阶段、跨切面架构改动、不安全到部分交付的迁移、跨多专家 lane 的持续协调。

**不要**仅因任务触及多文件就推断 deepwork。不要用于琐碎编辑、快速文档改动、简单 bug 修复、常规有界功能。

## 核心契约

deepwork 激活时,orchestrator 作为调度器管理,不作为默认实现工人。

## 设置与 deepwork 状态

- 创建并维护本地 markdown 进度文件于 `.bu-zhen/deepwork/`
- 代码/文档交付物存项目路径(如 `src/`、`docs/`);`.bu-zhen/deepwork/` 严格用于进度文件

### Deepwork 文件

创建任务专属文件:

```
.bu-zhen/deepwork/<short-task-slug>.md
```

创建前检查 `.gitignore` 和 `.ignore`,仅添加缺失项,不加重复:

```gitignore
# .gitignore
.bu-zhen/deepwork/
```

```gitignore
# .ignore
!.bu-zhen/deepwork/
!.bu-zhen/deepwork/**
```

不遵循僵化模板。选最适合工作的 markdown 结构。文件需作为持久会话状态保持有用,应含:

- 当前目标与理解
- 来自 librarian 的已研究、事实性上下文(避免 oracle 自行研究)
- 计划草案、Oracle 审查预算/gate、审查笔记
- 实现阶段与状态
- 验证结果
- 未解问题、阻塞、跟进

在重大决策、接受的研究、审查、阶段完成、验证结果、范围变更后更新此文件。记录接受的发现,引用本地文件路径而非复制内容。

## 规划

- 实现前起草计划
- 创建分阶段实现/委派计划
- 派发前,从工作依赖和自然交付边界选少量连贯实现阶段;不仅为缩小 Oracle 审查范围而拆分
- 执行前定义连贯交付阶段,每阶段后强制 `@oracle` 审查;在 deepwork 文件记录阶段顺序、专家所有权、gate 顺序、一行 gate 理由;与用户分享紧凑版
- 每阶段开始前,用该阶段可操作的交付 todo 替换 opencode todo 列表(仅该阶段)

## 阶段执行

每实现阶段前,决定执行路径:什么可并行、什么必须串行、委派哪些专家、是否把同一 agent 拆成多有界 lane。

### 调度器纪律

全程用调度器模型:
- 记录 task/session ID 与所有权边界
- 等待 hook 驱动的后台完成再消费后台结果
- 避免阻塞 orchestrator lane 同时后台任务在跑;若无独立工作剩余,短暂停止让完成事件恢复工作流
- 相关任务在跑或终局结果未调和时不前进到下一阶段

## 阶段门控与提交

- 每计划阶段后,跑相关验证,更新 deepwork 文件,然后请求计划的 `@oracle` gate 再继续
- Oracle gate 前,记录相关已接受研究和文件引用,使 Oracle 审查已建立的上下文而非重复发现
- 在 deepwork 文件记录阶段目标、改动路径、验证证据、要审查的具体决策或风险;把这些上下文连同已接受研究和文件引用提供给 Oracle
- 阶段改变模块边界、依赖方向或文件放置时,与 Oracle gate 并行跑 `@explorer` 结构扫描
- 调和审查发现,对实质问题执行一轮有界修复,用聚焦证据验证该轮
- 阶段为独立有效交付边界时,在开始下一阶段前创建聚焦提交

### Oracle 复查

每计划 Oracle gate 一次初查 + 最多两次复查。仅在修复实质性改变被审查决策/风险,或原关切无法用聚焦证据验证时请求复查。不把复查花在机械或已验证的改动上。

每次 Oracle prompt 中声明尝试:

```
Gate 2 — review attempt 2 of 3 (1 re-review remaining)
```

复查时,告诉 Oracle 优先处理未解的实质发现、修复引入的风险、先前发现是否已解决。不得重开已接受、未变、已解决的关切。两次复查耗尽后,在 deepwork 文件记录剩余实质风险或阻塞,问用户接受风险/改范围/授权额外审查。

## 设计师交接护栏

deepwork 阶段含 `@designer` 时,把交付的 UI/UX 视为后续阶段的已接受设计意图。继续前在 deepwork 文件记录重要设计决策。

designer 工作后:
- 保留布局、节奏、层次、动效、间距、色彩、affordances、响应式、组件感
- 用接地正常措辞审查并改进用户面文案,但不改视觉结构或交互意图
- 视觉/响应式/动效/层次/打磨/组件感改回交 `@designer`
- `@fixer` 仅做保留设计的有界机械跟进(接线、测试、类型修复、非视觉行为改动)
- 设计意图必须变时,改前在 deepwork 文件记录原因

## 完成时

- 最终验证与简明摘要

## 安全硬化叠加

deepwork 期间,[safety-hardening.md](safety-hardening.md) 的所有规则仍然生效,且:
- deepwork 进度文件本身不写入敏感目录(始终在 `.bu-zhen/deepwork/` 下)
- 每阶段提交前检查写范围未越界项目根
- 审查预算耗尽后不自动续期,必须用户授权
