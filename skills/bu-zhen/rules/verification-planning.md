# Verification Planning

为非平凡编码工作构建证据路径。在实现功能、修 bug、重构、跨系统改动、需可信项目专属证据路径的高置信行为改动前使用。

## 构建证据路径

改非平凡系统前,建一条**证据路径**:从要验证的声明,到能确立、限制或反驳它的证据。

目的不是选熟悉技术。目的是决定此系统如何揭示此特定改动的真相。

## 1. 构架声明

陈述需成为真的行为,以及可能使结论错误的条件。

考虑:什么必须变、什么必须保持真、行为在哪里跨边界、哪种失败最重要。

**完成当**:声明、其有意义的不确定性、其重要失败模式具体到可调查。

## 2. 设计证据路径

从系统本身推导可能路径:可控输入、可观测效果、状态转换、不变量、边界、产物、可重复或可逆场景。

选择前生成替代方案。优选以相称成本、安全、努力产出可信结论的路径。

**完成当**:有首选路径、其局限已理解、有可用的弱/强替代方案。

## 设验证预算

最终状态时,陈述各声明,每条指派一所有者确立或反驳,选最小非重复证据覆盖声明与重要边界。仅当相关代码、输入、环境、状态仍有效时复用证据。必需的仓库与发布检查仍适用;仅当陈述条件证明时扩大或重复验证。

## 3. 需要时创建验证 affordance

现有系统使决定性真相太间接或模糊时,用**验证 affordance** 扩展证据路径:使相关状态可控、可观测、可重复、可诊断的最小能力。

问什么能力能让 agent 直接确立声明、从已知状态重复场景、无推断地解释失败。优选增强直接性、确定性、agent 可读性、隔离、可重置或未来复用的 affordance。

把 affordance 视为证据路径的一部分,非自动产品特性。构建前慎重决定临时还是持久。

**完成当**:所选路径能足够直接确立声明,任何所需 affordance 有定义的生命周期。

## 4. 路径未知时研究

正确证据路径依赖不熟悉的依赖、框架、外部服务或快速变化的能力时,先请 `@librarian` 做聚焦研究。

请求官方或项目专属的设施、约束、权衡,影响此精确验证问题。已有项目证据能直接解决选择时直接用。

**完成当**:所选路径基于已知能力与真实约束,而非假设。

## 5. 使路径可跑

仅准备可靠跟随证据路径所需的支持。保持支持窄、可重复、可安全检查。

决定该支持有复用价值或仅为解决当前不确定。刻意保留持久价值;一旦临时支持已尽其用即移除。

引入依赖、持久诊断面、或仅为取证的结构改动前先问。

**完成当**:路径可跟随无需猜设置、状态或解释。

## 6. 关闭证据路径

实现后,跟随计划路径,把结果证据对照原始声明解读。

报告声明被确立、限制还是反驳;区分已知事实与剩余不确定。

**完成当**:未来读者能看到什么支持结论、什么超出结论范围。

## 范围

比例使用此技能。小机械改动可直接用普通项目检查。较大多阶段工作让此技能确立后续工作跟随的证据路径。

## 安全叠加

- 验证 affordance 若需引入新依赖 → 用户必须显式批准
- 持久诊断面的引入必须用户批准,且仅在其有复用价值时保留
- 证据路径不得读取敏感目录(`.ssh`、`.aws`、`.env*`、`*.key`)获取"证据"
- 验证命令遵循共享安全规则:显式 timeout、禁无范围全量测试
