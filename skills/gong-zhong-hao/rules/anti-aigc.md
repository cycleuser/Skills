# 存档报告与索引反AIGC / Anti-AIGC for Archives

存档报告与索引最容易写成"已成功抓取公众号全部文章"这类空话。用户要的是可核查的事实：抓了几篇、存哪、耗时、失败几篇、为什么。

## 1. 抓取报告带具体数字

```
❌ AI模式：
"已成功抓取公众号全部文章并保存为 Markdown。"

✅ 真实写法：
"抓取 128 篇，跳过 0 篇，失败 2 篇（1 篇 403 已删，1 篇转换异常存 HTML），
存档于 ~/WeChatArchives/某科技评论/，耗时 14 分钟，图片 312 张本地化。"
```

## 2. index.md 列具体条目

```
❌ AI模式：
"# 某科技评论文章存档
全部文章已保存。"

✅ 真实写法：
"# 某科技评论 文章索引

共 128 篇，抓取于 2026-07-29。

| 日期 | 标题 | 本地 |
|------|------|------|
| 2026-07-28 | 谈谈大模型的上下文窗口 | articles/20260728-谈谈大模型的上下文窗口.md |
| 2026-07-20 | 大模型推理优化实践 | articles/20260720-大模型推理优化实践.md |
| ... | ... | ... |"
```

## 3. 失败原因具体

```
❌ AI模式：
"部分文章抓取失败。"

✅ 真实写法：
"失败 2 篇：
  2026-05-10《某付费文章》→ paywalled（仅抓免费段）
  2026-03-15《已删除的文章》→ 403 deleted"
```

## 4. 增量报告带对比

```
❌ AI模式：
"已完成增量更新。"

✅ 真实写法：
"增量更新：上次 last_crawl=2026-07-01，本次新增 3 篇
（2026-07-15、2026-07-22、2026-07-28），存档总数 131 篇。"
```

## 5. 不堆砌"全面/完整/高效"

删掉"全面地""完整地""高效地""成功地"——直接给数字和路径。

## 自检 / Checklist

- [ ] 抓取报告带篇数、失败数、原因、存档路径、耗时
- [ ] index.md 列每篇标题+日期+本地路径
- [ ] 失败原因具体到 URL 与状态
- [ ] 增量报告带 last_crawl 与新增数对比
- [ ] 无"全面/完整/高效/成功"空转副词堆砌
