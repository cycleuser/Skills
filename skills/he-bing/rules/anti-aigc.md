# 流程文档反AIGC检测规则

流程类技能（PR管理、安全审计、迭代管理、自控等）的输出主要是流程描述、状态报告、配置文档。这类文档的AIGC问题不是文笔问题，而是**可执行性**问题。

## 核心原则

流程文档反AIGC的关键是：每个步骤是否可执行？AI流程文档读起来逻辑通顺但无法直接执行——缺命令、缺参数、缺判断条件。好流程文档读完后照着做就知道每一步干啥。

## 流程文档AIGC高发模式

### 1. 步骤不可执行（权重35%）

```
❌ AI模式：
"创建工作树"
"实施功能"
"运行测试"
"验证结果"

✅ 可执行步骤：
"git worktree add ../repo-wt/feature-auth feature/auth"
"在 core/auth.py 实现 JWTHandler 类，参考 core/session.py 的 RedisHandler 结构"
"pytest tests/test_auth.py -v --timeout=30"
"curl -X POST http://localhost:5000/api/auth/login -d 'user=test&pass=test' && echo '✅ login works'"
```

### 2. 判断条件模糊（权重25%）

```
❌ AI模式：
"如果测试通过，继续下一步"
"如果出现问题，进行修复"
"当测试覆盖率足够时，进入下一个阶段"

✅ 具体判断条件：
"如果 pytest tests/ -v 全部通过（退出码0），继续合并"
"如果 pytest 失败，查看失败日志，如果是import error：pip install -e . 后重试；如果是逻辑错误：修改代码后重试（最多3次）"
"测试覆盖率 >= 80%（用 pytest --cov 检查），低于80%时补充测试用例直到达标"
```

### 3. 错误处理笼统（权重20%）

```
❌ AI模式：
"如果出现错误，进行修复后继续"
"如果失败，尝试其他方案"

✅ 具体错误处理：
"如果 git push 失败：
  - 远程分支不存在：git push -u origin feature/auth
  - 权限不足：检查 gh auth status，重新 gh auth login
  - 网络超时：等待30秒后重试，最多3次"
```

### 4. 状态报告空洞（权重15%）

```
❌ AI模式：
"进展顺利"
"已完成大部分工作"
"遇到了一些问题"

✅ 具体状态：
"已完成 11/15 个任务（73%），剩余4个任务：密码重置(P1)、邮件验证(P1)、API限流(P2)、日志优化(P2)"
"P0密码重置功能：核心逻辑已实现，但邮件发送服务SMTP连接超时（3次重试均失败），标记[降级]：改为日志记录验证码代替邮件发送"
```

### 5. 配置参数无默认值和理由（权重5%）

```
❌ AI模式：
"配置迭代次数"
"设置超时时间"
"调整预算参数"

✅ 具体配置：
"max_iterations: 5  # 超过5轮改善率通常<1%，不建议增加
timeout: 30s        # 对齐 global-rules/bash-safety.md 的安全规则
budget_level: medium # 60分钟足够大部分任务，large(120min)仅用于多模块重构"
```

## 反AIGC五原则

### 1. 命令可复制粘贴

每个步骤的命令要完整到可以复制粘贴执行。

### 2. 判断条件可量化

用退出码、百分比、具体数值判断，不用"通过""足够""顺利"。

### 3. 错误处理有if-else

每种常见错误写明识别方法和处理步骤。

### 4. 状态有数字

不用"大部分""一些""顺利"，用11/15、3次、73%。

### 5. 配置有理由

每个配置参数写明默认值和选择理由。

## AIGC率检测清单

- [ ] 每个步骤是否可直接复制执行？→不可执行=AI
- [ ] 判断条件是否量化？→模糊=AI
- [ ] 错误处理是否有if-else？→笼统=AI
- [ ] 状态报告是否有数字？→空洞=AI
- [ ] 配置参数是否有默认值+理由？→无理由=AI

### AIGC率评分标准

- 0-15%：照着做就能完成，像资深工程师的操作手册
- 16-30%：合格，主要步骤可执行有个别模糊
- 31-50%：需要修改，像概述而非操作手册
- 51-70%：需要重写，全是空话
- 71-100%：纯AI生成的万能流程
