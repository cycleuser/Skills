# 回收日志反AIGC / Anti-AIGC for Trash Logs

参见 [_shared/core/anti-aigc.md](../../_shared/core/anti-aigc.md) 通用反AIGC规则。以下为回收/恢复报告的补充。

回收和恢复报告最容易写成"已安全处理""文件已恢复"这类空话。用户需要的是可核查的事实：哪个 id、原路径在哪、校验和对不对、多大、何时。

## 1. 每条结论都带可核查标识

```
❌ AI模式：
"文件已成功恢复到原位置。"

✅ 真实写法：
"恢复 id=20260729-1530-a1b2 → ./src/old_module.py，SHA-256 `a1b2c3d4e5f6...`
校验通过，4287 字节，mtime 2026-07-28 14:23。回收站原件保留，可再次恢复。"
```

没有 id、路径、校验和的"已恢复"都是空话。

## 2. purge 预览必须列具体条目

```
❌ AI模式：
"已清理 30 天前的旧条目，释放了空间。"

✅ 真实写法：
"将清理 3 条（30 天前）：
  20260628-1200-a1b2  ./tmp/old.log     1.2 KiB  2026-06-28
  20260625-0900-c3d4  ./build/out.txt  45 KiB   2026-06-25
  20260620-1800-eeee  ./notes/draft.md 8 KiB    2026-06-20
确认执行加 --confirm。大文件条目（large=true）内容留原位，只置 tombstone。"
```

## 3. 失败/拒绝要给具体原因

```
❌ AI模式：
"恢复失败，请重试。"

✅ 真实写法：
"拒绝恢复 id=20260729-1530-a1b2：SHA-256 校验失败（期望 `a1b2...`，实际 `e5f6...`），
回收站内容可能损坏或被篡改。建议从 git 或 Time Machine 恢复。"
```

## 4. 守护拦截要说清替代路径

```
❌ AI模式：
"检测到危险操作，已阻止。"

✅ 真实写法：
"守护模式拦截 `rm ./src/old.py`：改用 `/回收 delete ./src/old.py` 可入回收站。
执行后 id 将记录到 manifest.jsonl，可用 `/回收 restore <id>` 恢复。"
```

## 5. 不堆砌"安全/可靠/完善"等空转形容词

删掉"安全地""可靠地""完善地""全面地"——直接给事实。每千字空转副词超过 3 处即过量。

## 自检 / Checklist

- [ ] 每条恢复/删除结论都带 id、路径、校验和、大小
- [ ] purge 预览列出具体 id 与原路径
- [ ] 失败/拒绝带具体原因与建议
- [ ] 守护拦截给出替代命令
- [ ] 无"安全/可靠/完善"空转副词堆砌
