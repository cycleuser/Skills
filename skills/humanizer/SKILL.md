# 人话 (Humanizer)

AI文本人化处理技能 - 基于AIGC检测原理，将AI生成文本转化为自然人类语言。

## Quick Commands

| Command | Description |
|---------|-------------|
| `/人话 <文本>` | 对输入文本进行人化处理 |
| `/人话 --style formal <文本>` | 书面化人化处理 |
| `/人话 --style casual <文本>` | 口语化人化处理 |
| `/humanize <text>` | Humanize AI-generated text (English) |
| `/detect <文本>` | 分析文本的AI特征 |
| `/demo` | 生成示例并演示完整处理流程 |

## AIGC检测原理与反检测策略

### 主流检测方法

AIGC检测器主要基于以下原理工作：

```
┌─────────────────────────────────────────────────────────────────┐
│                    AIGC检测的核心维度                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 困惑度 (Perplexity)                                         │
│     ─────────────────────────────────────────────               │
│     检测原理: AI倾向于选择概率最高的词，困惑度低                  │
│     人类写作：困惑度高，会使用意外的词汇                          │
│     AI文本：困惑度低，用词"安全"、"正确"                         │
│                                                                 │
│  2. 突发性 (Burstiness)                                         │
│     ─────────────────────────────────────────────               │
│     检测原理: 人类写作的句子长度和复杂度变化大                    │
│     人类写作：长短句穿插，节奏跳跃                                │
│     AI文本：句子长度均匀，节奏平稳                                │
│                                                                 │
│  3. 词汇分布 (Token Distribution)                               │
│     ─────────────────────────────────────────────               │
│     检测原理: AI偏好常见词，人类会用更丰富的词汇                  │
│     人类写作：词汇多样，有生僻词、口语词                          │
│     AI文本：词汇集中在高频区域                                    │
│                                                                 │
│  4. 句式模式 (Sentence Pattern)                                 │
│     ─────────────────────────────────────────────               │
│     检测原理: AI句式结构更规整、对称                              │
│     人类写作：句式多变，有倒装、省略、插入语                      │
│     AI文本：句式工整，主谓宾结构稳定                              │
│                                                                 │
│  5. 过渡词频率 (Transition Words)                               │
│     ─────────────────────────────────────────────               │
│     检测原理: AI过度使用正式过渡词                                │
│     人类写作：过渡自然，少用"首先其次"                            │
│     AI文本：过度依赖"首先、其次、综上所述"                        │
│                                                                 │
│  6. 内容深度 (Content Depth)                                    │
│     ─────────────────────────────────────────────               │
│     检测原理: AI内容停留在概念层面                                │
│     人类写作：有具体案例、数据、个人经历                          │
│     AI文本：概念罗列，缺乏具体细节                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 反检测策略总表

| 检测维度 | AI特征 | 反检测策略 |
|---------|-------|-----------|
| 困惑度 | 用词"安全"、常见 | 使用意外的词汇、生僻词、口语词 |
| 突发性 | 句子长度均匀 | 长短句穿插，制造节奏变化 |
| 词汇分布 | 高频词为主 | 引入低频词、专业术语、俚语 |
| 句式模式 | 结构规整对称 | 打破对称，用倒装、省略、插入语 |
| 过渡词 | 过度使用正式过渡词 | 删除或替换为自然过渡 |
| 内容深度 | 概念空洞 | 加入具体数据、案例、细节 |

## 反检测详细策略

### 策略1: 提高困惑度

**原理**: AI倾向于选择最可能的词汇，困惑度低。人类会使用"意外"的词汇。

```
❌ AI文本 (困惑度低):
人工智能技术在教育领域具有重要应用价值，能够实现
个性化教学，提高教学效率。

✓ 人化处理 (困惑度高):
AI进教育这事儿，说白了就是想让机器帮老师"因材施教"。
理想挺丰满，现实嘛...参差不齐。
```

**操作方法**:
- 用具体词汇替换抽象词汇
- 用口语词替换书面词
- 用意外表达替换"正确"表达
- 加入个人感受和判断

**困惑度提升词汇表**:

| AI常用词 | 人化替换 |
|---------|---------|
| 重要意义 | 关键在于、核心问题是 |
| 显著提高 | 提了点、有点起色、好歹改善了 |
| 广阔前景 | 这条路能走、有机会、但也不是铁定的 |
| 具有优势 | 占点便宜、有点长处 |
| 需要注意 | 问题来了、关键问题是 |

### 策略2: 增加突发性

**原理**: AI句子长度均匀，人类长短句穿插。

```
❌ AI文本 (突发性低):
人工智能在医疗领域具有广泛应用前景。
区块链技术为数据安全提供了新的解决方案。
云计算平台降低了企业的IT基础设施成本。

✓ 人化处理 (突发性高):
AI在医疗领域的应用前景广阔。区块链解决了数据安全问题，
云计算则让企业的IT成本大幅下降——这三者正在重塑技术格局。
说到底，都是围绕"降本增效"打转。
```

**操作方法**:
- 合并短句成长句
- 拆分长句成短句
- 加入极短的判断句（3-8字）
- 制造节奏变化

**突发性增强模式**:

```
模式1: 长句 + 短判断
...（30字以上的长句）。这就是问题所在。
...（复杂论述）。很难。

模式2: 短句 + 解释
为什么？因为...
核心是什么？是...

模式3: 多短句连击
这事不简单。涉及面广。利益盘根错节。
```

### 策略3: 丰富词汇分布

**原理**: AI词汇集中，人类词汇多样。

```
❌ AI文本 (词汇单调):
该系统具有良好的扩展性，能够实现高效的资源调度，
为用户提供优质的服务体验。

✓ 人化处理 (词汇丰富):
这套系统可以横向扩展，资源调度还算灵活，
用户体验——至少我用下来——还行。
```

**操作方法**:
- 引入专业术语
- 引入口语词/俚语
- 引入方言或网络用语
- 避免重复用词

**词汇替换表**:

| AI高频词 | 人化低频词 |
|---------|-----------|
| 实现 | 搞定、弄成、跑通 |
| 进行 | 干、做、弄 |
| 具有 | 有、带着、有着 |
| 能够 | 可以、能、搞得定 |
| 提供 | 给、贡献、递过来 |
| 需要 | 得、必须、少不了 |

### 策略4: 打破句式模式

**原理**: AI句式工整，人类句式多变。

```
❌ AI文本 (句式单调):
从技术角度来看，人工智能具有强大的数据处理能力。
从应用层面分析，AI已经渗透到各行各业。
从发展趋势预测，人工智能将成为未来的核心技术。

✓ 人化处理 (句式多变):
人工智能的核心优势？数据处理能力。这一点在各行各业的应用中
已经得到验证——医疗诊断、金融风控、智能制造，
几乎没有AI涉足不到的领域。未来的核心技术？大概率就是它了。
```

**操作方法**:
- 使用倒装句
- 使用省略句
- 加入插入语
- 使用问句

**句式变换模式**:

```
原句: A具有B的特点

变换1 (倒装): B，这是A的典型特征
变换2 (省略): A？B是肯定的
变换3 (插入): A，在我看来，具有B的特点
变换4 (问句): A有什么特点？B
```

### 策略5: 删除/替换过渡词

**原理**: AI过度使用正式过渡词。

```
❌ AI过渡词:
首先，...其次，...最后，...
一方面，...另一方面，...
综上所述，...
需要指出的是，...

✓ 人化过渡:
（删除"首先"，直接开始）
再说一点：...
还有个问题是...
说到底，...
关键在于，...
```

**过渡词替换表**:

| AI过渡词 | 人化替代 |
|---------|---------|
| 首先 | （删除） |
| 其次 | 再说一点、另外 |
| 最后 | 最后一点、补充一句 |
| 综上所述 | 说到底、归根结底 |
| 一方面...另一方面 | 先说...再说...、...但... |
| 需要指出的是 | 问题在于、关键是 |
| 值得注意的是 | 有意思的是、值得注意的是 |
| 从...角度来看 | 具体到...、在...方面 |

### 策略6: 增加内容深度

**原理**: AI内容空洞，人类内容具体。

```
❌ AI文本 (内容空洞):
该政策取得了显著成效，促进了相关行业的发展，
创造了大量就业机会。

✓ 人化处理 (内容具体):
政策实施三年来，参与企业从200家增至1500家，
年均增长率超过90%。但真正达到标准的只有35%左右——
"参与"和"达标"之间，差距不小。
```

**操作方法**:
- 加入具体数字
- 加入具体案例
- 加入具体时间/地点
- 加入个人观察

**深度增强检查清单**:

```
□ 有没有具体数字？
□ 有没有具体案例？
□ 有没有对比数据？
□ 有没有个人判断？
□ 有没有反面观点？
```

## "一眼AI"特征库

### 最典型的"一眼AI"模式

这些模式几乎100%表明是AI生成：

#### 模式1: 加粗标题+冒号+相似句式

```
❌ AI典型写法:

**其一，信息来源分散。** 用户在多个网站、APP 之间反复切换，时间成本高企。

**其二，语言障碍突出。** 小语种信息的获取与理解，对普通用户而言几乎不可能。

**其三，处理能力有限。** 海量信息涌入后，提炼核心观点需要大量时间。
```

**问题分析:**
- 加粗格式过于整齐
- "其一、其二、其三"机械过渡
- 每句结构高度相似："主语+谓语+形容词/动词短语。后果描述。"
- 冒号后的句子长度相近

**人化处理:**
```
✓ 人写风格:

用户在多个网站和APP之间来回切换，时间成本高。
语言障碍也是个问题——小语种信息，普通人根本看不懂。
更头疼的是，信息量太大，想提炼核心观点得花不少时间。
```

#### 模式2: "首先...其次...最后..."机械三段论

```
❌ AI典型写法:

首先，从技术角度来看，人工智能具有强大的数据处理能力。
其次，从应用层面分析，AI已经渗透到各行各业。
最后，从发展趋势预测，人工智能将成为未来的核心技术。
```

**问题分析:**
- "从...角度/层面"高度重复
- 每段结构几乎一致
- 三个段落长度相近

**人化处理:**
```
✓ 人写风格:

人工智能的核心优势在于数据处理能力。这一点在当前的应用中
已经得到验证——从医疗诊断到金融风控，AI的渗透速度超乎想象。
但更值得关注的是其发展潜力。我认为，AI很可能成为下一个
技术革命的核心驱动力。
```

#### 模式3: "一方面...另一方面..."对称结构

```
❌ AI典型写法:

一方面，区块链技术具有去中心化、不可篡改等优势；
另一方面，其扩展性和性能问题仍是亟待解决的挑战。
```

**人化处理:**
```
✓ 人写风格:

区块链的去中心化和不可篡改性确实是其核心优势。
但问题也很明显——扩展性和性能瓶颈一直没解决。
```

#### 模式4: "综上所述/总而言之"总结句

```
❌ AI典型写法:

综上所述，人工智能技术的发展前景广阔，但同时也面临诸多挑战。
我们需要在推动技术创新的同时，关注其潜在风险。

总而言之，可持续发展是人类社会面临的重大课题，需要各方共同努力。
```

**人化处理:**
```
✓ 人写风格:

AI技术的发展前景确实值得期待，但风险也不容忽视。
关键在于如何在创新和风险之间找到平衡。

可持续发展这条路，注定不会平坦。能不能走下去，取决于
激励机制能否真正改变——光靠道德呼吁，恐怕远远不够。
```

## AI文本检测特征库

### 一、"一眼AI"的结构特征

| 特征 | AI典型表现 | 问题 |
|-----|-----------|------|
| 机械编号 | 其一...其二...其三... | 过于整齐 |
| 机械三段 | 首先...其次...最后... | 结构单调 |
| 机械对称 | 一方面...另一方面... | 缺少侧重 |
| 机械总结 | 综上所述/总而言之 | 公式化收尾 |
| 加粗标题 | **标题。** 内容... | 格式过于工整 |
| 冒号并列 | 标题：说明。 | 句式重复 |

### 二、"一眼AI"的语言特征

| 特征类型 | AI常用表达 | 人化替换 |
|----------|------------|---------|
| 空洞套话 | 具有...意义、起到...作用 | 删除或换具体内容 |
| 中立表述 | 既有优势也有不足 | 给出明确判断 |
| 绝对表述 | 必将...、一定能够... | 用"或许""可能" |
| 大词堆砌 | 深远意义、广阔前景、重大突破 | 用具体数据或删除 |
| 公式过渡 | 需要指出的是、值得注意的是 | 删除或融入正文 |
| 从句套从句 | 从...角度来看，... | 直接陈述观点 |

### 三、"一眼AI"的内容特征

| 特征 | AI表现 | 人化方向 |
|-----|-------|---------|
| 面面俱到 | 从A、B、C三个角度分析 | 只写一个核心观点 |
| 中立无立场 | 既有优点也有缺点 | 表达明确判断 |
| 概念空转 | 在概念层面打转 | 用具体案例、数据 |
| 缺少痕迹 | 结论确定 | 展现思考过程 |

## 核心处理策略

### 策略1: 打破整齐结构

**原则**: 人写的文章不可能那么整齐

```
❌ AI: 三点并列，每点格式相同
**其一，...。** ...
**其二，...。** ...
**其三，...。** ...

✓ 人化: 有详有略，格式不一
第一个问题比较突出：...（详细展开）

另外两个问题也值得关注。语言障碍方面，...（简略带过）
至于处理能力，其实取决于用户的信息素养。
```

### 策略2: 删除加粗和编号

**原则**: 真正的文章很少用"其一其二其三"

```
❌ AI:
**其一，技术门槛高。** 中小企业缺乏技术人才。
**其二，资金投入大。** 数字化转型需要大量前期投入。

✓ 人化:
技术门槛是个现实问题。不少中小企业连像样的IT团队都没有，
想搞数字化，光招人就够头疼的。

资金也是道坎。动辄几百万的投入，对很多企业来说不是小数目。
```

### 策略3: 用口语化过渡替代公式过渡

```
AI公式过渡 → 人化替代

综上所述 → （删除，或直接说结论）
需要指出的是 → （删除）
值得注意的是 → 值得一提的是 / 问题是 / 值得关注的是
从...角度来看 → 具体到... / 在...方面
一方面...另一方面 → 先说...再说... / ...但...
```

### 策略4: 打散句式结构

**原则**: 人写的句子长短不一，AI写的句子长度相近

```
❌ AI (每句长度相近):
人工智能技术在医疗领域具有广泛应用前景。
区块链技术为数据安全提供了新的解决方案。
云计算平台降低了企业的IT基础设施成本。

✓ 人化 (长短不一):
AI在医疗领域的应用前景广阔。区块链解决了数据安全问题，
云计算则让企业的IT成本大幅下降——这三者正在重塑技术格局。
```

## 处理示例

### 示例1: 打破"其一其二其三"

```
输入 (AI率 98%):

**其一，信息来源分散。** 用户在多个网站、APP 之间反复切换，时间成本高企。

**其三，处理能力有限。** 海量信息涌入后，提炼核心观点需要大量时间。

---

处理步骤:
1. 删除加粗和"其一其二其三"
2. 打散句式结构
3. 用口语化表达
4. 有详有略

---

输出 (AI率 25%):

用户面临的第一个问题是信息来源分散——在不同网站和APP之间来回切换，
时间成本相当高。语言障碍也不容忽视，小语种信息普通人根本看不懂。
至于处理能力，海量信息涌入后想提炼核心观点，确实需要花不少时间。
```

不追求全面，聚焦核心问题

### 2. 有立场

## AIGC检测方法总结

基于主流检测器(GPTZero、Turnitin等)的技术原理：

### 检测维度与反检测策略

| 维度 | 检测原理 | AI特征 | 反检测操作 |
|-----|---------|-------|-----------|
| **困惑度** | AI选择高概率词 | 用词安全、常见 | 用意外词汇、口语词、生僻词 |
| **突发性** | 句子长度变化 | 长度均匀 | 长短句穿插，制造节奏变化 |
| **词汇分布** | 词频分析 | 集中高频区 | 引入低频词、专业术语、俚语 |
| **句式模式** | 模板匹配 | 结构规整对称 | 倒装、省略、插入语、问句 |
| **过渡词** | 频率统计 | 过度使用 | 删除或替换为自然过渡 |
| **段落结构** | 结构分析 | 对称工整 | 有详有略，打破对称 |
| **内容深度** | 语义分析 | 概念空洞 | 加入数据、案例、个人判断 |

### 主流检测技术

1. **困惑度计算**: 预测下一个词的不确定性，AI文本困惑度低
2. **突发性分析**: 句子长度方差，AI方差小
3. **深度学习分类**: 句子级神经网络分类器
4. **三分类输出**: HUMAN_ONLY / AI_ONLY / MIXED

### 检测器局限

- 易误报：ESL写作者、规范性文本、简洁文本
- 易漏报：高质量AI文本、人工修改后的文本

详细方法见 [rules/detection-methods.md](rules/detection-methods.md)
