# 量化指标与阈值

这份文件回答"改到什么程度算改好了"。所有阈值都是经验值，来源见 `references/ai-text-features-research.md`；实测工具是 `scripts/humanize_lint.py`。

原则：**阈值用于收敛，不用于判定**。一项超线不构成改写理由，三项以上同时超线、且读起来确实不对，才动手。

---

## 一、怎么跑

```bash
# 详细报告（中文）
python3 scripts/humanize_lint.py check draft.md --lang zh --profile prose

# 一行摘要，适合批量看
python3 scripts/humanize_lint.py score draft.md

# 机器可读，适合写进流程
python3 scripts/humanize_lint.py check draft.md --json

# 从 stdin 读
cat draft.md | python3 scripts/humanize_lint.py check - --lang en

# 列出所有检测项
python3 scripts/humanize_lint.py rules
```

退出码：分数 ≤ 阈值返回 0，超过返回 1。可以用于"改到通过为止"的循环。

分数含义：

| 分数 | 档位 | 该怎么处理 |
|------|------|-----------|
| < 15 | 低 | 不必改；再改容易改坏 |
| 15–40 | 轻 | 只处理命中里权重最高的 1–2 类 |
| 40–62 | 中 | 按 rewrite-protocol 走完整五遍 |
| > 62 | 高 | 建议重写而不是修，句法骨架已经不对了 |

## 二、三套文体档位

不同文体的基线不同，用 `--profile` 切换。数值是"每千字/千词"的密度上限。

| 指标 | prose（散文/公众号/博客） | tech（技术文档） | academic（论文/报告） |
|------|--------------------------|------------------|----------------------|
| 加粗 | 允许 1 处；超过后 1→3 计分，3 满分 | 允许 3 处；2→6 | 不允许；0.5→2 |
| 破折号 | 允许 1 处；1→3 | 允许 2 处；1→3 | 允许 2 处；1→3 |
| 列表行占比 | 允许 1 行；0.06→0.15 | 允许 8 行；0.15→0.35 | 允许 2 行；0.05→0.20 |
| 三项并列 / 千字（中） | 0.4→1.2 | 0.8→2.0 | 0.5→1.5 |
| 三项并列 / 千词（英） | 0.8→2.2 | 1.2→3.0 | 0.8→2.0 |
| 句长 CV（越大越好） | ≤0.32 满分，≥0.55 免罚 | ≤0.25，≥0.48 | ≤0.18，≥0.38 |
| 段长 CV（≥4 段才计） | ≤0.20，≥0.55 | ≤0.20，≥0.55 | ≤0.15，≥0.45 |
| 通过分数 | 45 | 55 | 50 |

区间写法说明：`a→b` 表示测值 ≤a 不计分、≥b 满分，中间线性。`允许 N 处` 是出现次数豁免——短文本里出现一两个加粗或破折号属于正常写作，不该判 AI。

选错档位的后果：拿 prose 的标准审 API 文档，会把必要的列表全删掉。见 SKILL.md 的文体判定。

## 三、中文阈值

| 指标 | 人写常见 | AI 常见 | 处理线 | 说明 |
|------|----------|---------|--------|------|
| 平均句长 | 18–32 字 | 30–45 字 | >38 字收尾（仅提示，不计分） | AI 靠修饰语把句子拉长（对照研究：句法树高 >14 的句子比例显著高于人类，人类约 48%） |
| 句长变异系数 CV | 0.45–0.9 | 0.15–0.35 | ≤0.32 满分，≥0.55 免罚 | 要的是方差，不是"都短" |
| 段落长度 CV | 0.5–1.2 | 0.1–0.3 | ≤0.20 满分，≥0.55 免罚（≥4 段才计） | 每段都差不多长最可疑 |
| 官腔/空话词 | 0–3/千字 | 8–25/千字 | 3→15/千字 | 见 zh-patterns 词表 |
| 名词化动词（进行/开展/推进…） | 3–8/千字 | 12–25/千字 | 8→18/千字 | Z08 |
| 四字格/成语 | 1–3/百字 | 4–8/百字 | 2.5→6/百字 | Z20，公文另计 |
| 三项并列 | 0.2–0.8/千字 | 2–6/千字 | 0.4→1.2/千字 | Z06 |
| 否定平行 | 0–0.5/千字 | 1.5–4/千字 | 0.3→1.5/千字 | Z05 |
| 连接词开场句占比 | 5–15% | 25–45% | 10%→35% | Z26，学术放宽到 25% |
| 段首短判断句 | 少见 | 每 2–3 段一处 | 不计分，报告单列 | Z29 |
| 重复 4-gram 占比 | 0.03–0.10 | 0.15–0.30 | 0.06→0.22 | 论元复用的代理指标 |
| 字符 TTR（>300 字样本） | 0.40–0.55 | 0.28–0.38 | 只报数，不计分 | 只作参考，短文本不可靠 |
| 加粗 | 0 | 5–20/千字 | 1→3/千字（允许 1 处） | Z24 |
| 破折号（——） | 0–1/千字 | 1.5–4/千字 | 1→3/千字（允许 1 处） | Z24 |
| emoji | 0（散文） | 0.5–3/千字 | >0 | Z24 |
| markdown 残留 | 0 | 有 | >0 | 纯文本场景 |

中文特有提醒：

- **标点偏好**：AI 中文爱用「；」和「——」制造层次，人类更常用句号断开。分号密度超过 3/千字要看一眼。
- **「的」字链**：连续三个以上"的"（`对……的……的……的`）是修饰语过密的直接证据，出现就拆句。
- **主语缺失**：AI 中文常整段无主语，读起来像通稿。人写的说明文会交代"谁"。

## 四、英文阈值

| 指标 | 人写常见 | AI 常见 | 处理线 | 依据 |
|------|----------|---------|--------|------|
| 平均句长 | 12–20 词 | 18–26 词 | >24 词 | 注意新模型转为 8–20 词窄带，见"突发性" |
| 句长 CV | 0.45–0.85 | 0.20–0.35 | <0.40 | 同上 |
| 段落 CV | 0.5–1.1 | 0.15–0.35 | <0.35 | |
| AI 词表密度 | 0–2/千词 | 6–25/千词 | 3→15/千词 | Reinhart 2025 单词最高 162× |
| 名词化比例 | 2.5%–4% | 5%–8% | 4.5%→10% | 2.1× |
| 现在分词尾巴 | 0.5–2/千词 | 6–15/千词 | 每条命中计，看密度 | 5.3× |
| that 从句作主语 | 罕见 | 常见 | 出现 2 次以上看 | 2.6× |
| 三项并列 | 1–3/千词 | 6–15/千词 | 0.8→2.2/千词 | 4× |
| 否定平行 | 0.2–0.8/千词 | 1.5–4/千词 | 0.3→1.5/千词 | 3× |
| 连接词开头句 | 8–18% | 25–40% | 10%→35% | |
| 加粗 | 0（散文） | 20–60/千词 | 1→3/千词（允许 1 处） | 43× |
| 破折号 | 0.2–0.8/千词 | 2–6/千词 | 1→3/千词（允许 1 处） | 10×，但 Gemini 0.7× |
| 项目符号行 | 0–3/千词 | 10–30/千词 | 0.06→0.15 行占比（允许 1 行） | 9× |
| emoji | 0.05–0.15/千词 | 0.1–0.3/千词 | 看类型不看数量 | ✅ 167×、😊 0.6× |
| 弯引号 | 视文体 | ChatGPT/DeepSeek 默认 | 纯文本 >0 | 弱信号 |
| 无施事被动 | 基准 | **约人类一半** | 不要硬加被动 | 0.5× |

英文特有提醒：

- **不要为降分加被动**。这是最常见的误改（E08）。
- **缩写与数字**：`Dr.`、`e.g.`、`3.5` 会让天真的分句器出错。本技能的脚本已处理常见缩写，其他工具未必。
- **新模型窄带**：2026 年的模型倾向 8–20 词的短句群。如果一段全是 12 词左右的句子，CV 会偏低——这正是要抓的。

## 五、四维分项怎么读

报告里的四个分项各自独立，不要只看总分：

| 分项 | 高说明什么 | 先做什么 |
|------|-----------|---------|
| 结构 | 段落太齐、版面痕迹重、句子长度均匀 | 打散段落、清版面、造长短句 |
| 词汇 | 空话/AI 词/名词化密度高 | 按词表替换或删除 |
| 句式 | 三项并列、否定平行、连接词开场、句式同构 | 破结构，改主语和语序 |
| 残留 | markdown、emoji、弯引号、非常规符号 | 机械清理 |
| 信号 | 命中了多少个不同的检测项 | 信号数比单项强度更重要 |

经验：**信号分高、其他分低**，说明文字短但踩了好几个典型坑，通常改三四处就能明显改善；**结构分高、信号分低**，说明是排版问题，机械清理即可。

---

## 六、分数不能告诉你的事

1. 不能判断作者。分数低不代表人写，分数高不代表 AI 写。
2. 不能判断事实。编造的数字、错误的引用，指标完全看不出来——那是 `/有据` 的活。
3. 不能判断叙事。说教、线性、回避道德模糊，只能靠人读。
4. 不能跨语言比较。中文 40 分与英文 40 分不是一回事。
5. 不能用于学术不端指控。任何检测分数都不足以作为证据。

写进交付报告时，务必带上这句限定：**这是启发式体检，不是检测结论**。

---

## 七、阈值怎么调

如果某个文体持续误报（例如内部周报总被判"中"）：

1. 先确认档位对不对（`--profile tech` / `academic`）；
2. 连续 5 篇人写样本取中位数，用中位数的 1.5 倍作为新阈值；
3. 改 `scripts/humanize_lint.py` 里 `PROFILES` 或对应 `ramp_*` 的上下界；
4. 跑 `python3 tests/test_lint.py`，确认四份样本的排序没被破坏。

不要为了让某篇文章"通过"而临时改阈值。
