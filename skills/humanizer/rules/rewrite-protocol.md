# 改写协议（五遍法）

这套流程把"去 AI 味"拆成可执行、可复核的步骤。顺序不能乱：先保内容，再破结构，再改句法，再换词，最后清版面。反过来做（先换词）通常改不干净，因为骨架还是 AI 的。

适用两种模式：

- **light（润色）**：文本本身内容可用，只想让它读起来更像人。只做 P1 的一部分 + P3 + P5。
- **full（重写）**：AI 痕迹密集，或要改成特定作者口吻。五遍全做。

模式怎么定：先跑 `humanize_lint.py check`。分数 <15 用 light 或不动；15–40 用 light；>40 用 full。

---

## P0 保全：先划白名单

动手前把这些标记为**不可改**，改写过程中原样复制：

| 类型 | 例子 |
|------|------|
| 数字与单位 | 78.4、0.12%、280 Ma、3.5 s |
| 专有名词 | 产品名、人名、机构名、地名、型号 |
| 术语 | 领域内固定译名（见"术语不动"原则） |
| 引用与链接 | `[1]`、DOI、URL、脚注编号 |
| 代码与命令 | 代码块、行内代码、路径、环境变量 |
| 直接引语 | 引号内的原话，一个字都不动 |
| 法律/医疗限定语 | "可能""在医生指导下""不构成建议" |

同时记下**原文的核心主张**（一两句），改写完成后逐条对照：主张是否还在、条件是否还在、强度是否被改大或改小。

**铁律：具体化只能来自作者。** 原文没有的数据、案例、经历，一律不许补。需要补的地方写 `（待补：……）`，并说明需要什么。

---

## P1 骨架：删与并

目标是把"结构上的 AI 感"去掉。动作全是减法。

1. **删**公式化开头（Z12/E09）、公式化收尾（Z03/E13）、免责声明（E11）、助手残留（E10）。这几类通常整段删。
2. **删**空话与拔高（Z01/E01）：把"具有重要意义"整句拿掉，看剩下的句子是否成立。成立就删。
3. **破**三段论（Z02）：去掉序数词，按因果或时间重排；三块内容允许变成两块或四块。
4. **破**对称结构（Z04）：挑一方为主，另一方降为从句或删掉。
5. **合/拆段落**：让段落长度出现明显差异——一段 3 行，一段 8 行，一段 1 行。段段等长是最明显的机器痕迹。
6. **定视角**：这段是谁在说？对谁说？如果是说明文，删掉"我们/大家"；如果是经验帖，保留第一人称并写明"我"做了什么。

P1 之后重跑一次 lint：结构分应该明显下降，信号分不变（词还没换）。

---

## P2 句法：造长短句

目标是把"句法层的 AI 感"去掉。这一遍决定读起来像不像人。

1. **拆名词化**：中文"对……进行优化"→"优化了……"；英文 `the implementation of X`→`we implemented X`。
2. **去 -ing 尾巴**（E04）：`…, highlighting the importance of X` 改成独立句，或删。
3. **砍三项并列**（Z06/E06）：三项→两项，或一项+具体例子。
4. **改否定平行**（Z05/E05）：直接说结论；全文最多留一处。
5. **造方差**：每 3–5 句里放一个短句（中文 4–8 字，英文 3–6 词）；每段里至少一个 30 字以上的长句。不要把句子全改短——全短也是 AI 特征。
6. **改语序**：把状语调到句首或句尾，允许一次倒装或插入语。
7. **中文加互动**：适当用"你""其实""大概""我没验过"这类标记，但不要每句都加。
8. **英文用短动词**：utilize→use，facilitate→help，endeavor→try。

P2 之后句长 CV 应升到 0.45 以上，名词化比例降到阈值内。

---

## P3 词汇：换与删

1. 按 `zh-patterns.md` / `en-patterns.md` 的词表处理，**按密度处理，不按单词处理**。同一个词出现一次不动，出现五次才考虑。
2. 换词的标准是"你会不会这么说"。换不出来就删掉整个短语。
3. 中文：官腔词（赋能/闭环/抓手）换具体动作；抽象后缀（性/化/度）还原；成语只留最贴切的一个。
4. 英文：AI 词表换成日常词；营销动词换成 has/does/costs/takes。
5. 保留专业术语。把"背压"改成"往回顶的压力"是错的；把"闭环反馈"改成"反馈回路"要看领域。
6. 不要为了"高级"换成更生僻的词。人写东西用常用词，只是用得准。

---

## P4 证据与痕迹

这一遍决定文字有没有"人味"，也是最难自动化的一遍。

1. **补真实细节**：作者提供的数字、时间、地点、失败经历。没有就留 `（待补）`。
2. **给判断**：把"各有优劣"改成"我选 A，因为……"。允许判断有偏差，人本来就有偏差。
3. **留不确定**：一处"我不确定""样本很小""这条没验证"。不要每段都留，一处就够。
4. **去说教**：删掉"这个故事告诉我们""真正重要的是"这类句子；让事实自己说话。
5. **允许不完整**：不必每段都有主题句，不必每篇都有总结。人可以写到一半停。
6. **检查叙事**：如果全文是单线推进、每个问题都有答案、没有取舍，读者的直觉仍会判定"不像人写的"。这一层只能靠作者补经历。

## P5 版面：清零

| 项目 | 散文 | 技术文档 | 学术 |
|------|------|----------|------|
| 加粗 | 清零 | 仅术语首次出现 | 基本清零 |
| 列表 | 转成句子 | 保留但去掉粗体标签 | 少用 |
| 表格 | 转成句子 | 保留矩阵数据 | 保留数据表 |
| emoji | 清零 | 清零 | 清零 |
| markdown 残留 | 清零 | 保留（本来就是 md） | 按载体 |
| 破折号 | 减到 1/千字以内 | 同上 | 同上 |
| 弯引号 | 与全文统一 | 统一直引号 | 按期刊要求 |

中文还要检查：全角标点是否统一、中英文之间是否加空格（按目标平台规范）、数字是否用半角。

## 自检清单（10 条，≥8 条才算可交付）

- [ ] 核心主张与原文一致，条件和强度没有被改大或改小
- [ ] 所有数字、术语、引用、代码与原文逐字一致
- [ ] 没有任何原文没有的具体事实（数据、案例、经历）
- [ ] 没有连续三段等长；段落长度有明显差异
- [ ] 句长有长短交错，最短句 ≤8 字（中文）/≤6 词（英文）
- [ ] 三段论、三项并列、否定平行各不超过 1 处
- [ ] 空话/官腔词密度在阈值内（跑 lint 确认）
- [ ] 散文里没有加粗、列表、表格、emoji、markdown 残留
- [ ] 留了一处不确定性或判断，读起来有"人"的痕迹
- [ ] lint 分数 ≤ 对应 profile 的阈值

未达标的项写进交付报告，不要隐瞒。

## 常见误改（比 AI 味更糟）

1. **全改短句**：以为短句=人味，结果每句五个字，读起来像口播稿。人写东西有长句。
2. **硬加被动/硬去被动**：英文 AI 的无施事被动本来就比人少（0.5×），再去被动是反方向。
3. **术语口语化**：把专业术语换成大白话，读者（同行）会觉得不专业，且可能改变含义。
4. **过度加语气词**：每句都"其实""说实话""吧"，比 AI 还假。
5. **编造细节**：为了"具体"编一个项目、一个客户、一个数字。这是造假，不是润色。
6. **删掉必要的限定**：把"在多数场景下"删掉，主张强度被放大，属于改变原意。
7. **把判断改成反问**：`这真的可行吗？` 看起来像人，实际是另一种套话。
8. **同义词轮换**：为了避免重复把"模型"换成"算法""系统""引擎"，指代混乱。
9. **破坏格式**：把作者精心排的表格拆成散文，损失信息。
10. **为过 lint 而改**：分数是体温计，不是目标。改到 30 分但意思变了，等于失败。

## 交付格式

默认给三段，不要长篇解释：

1. **改写稿**（正文，不带"以下是"之类的话）
2. **改动摘要**（3–6 条，只说做了什么级别的改动，例如"删了三段公式化开头；把 12 处名词化还原为动词；清理了全部加粗与列表"）
3. **前后指标**（lint 分数与关键密度，附一句限定：这是启发式体检，不是检测结论）

如果用户只要正文，就只给正文。如果用户要审阅意见而不是改写，就只给意见 + 命中清单，不要擅自改稿。

遇到必须作者补内容的地方，用 `（待补：具体需要什么）` 标出，并在摘要里说明有几处。
