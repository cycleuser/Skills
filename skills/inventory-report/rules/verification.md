# 多源交叉核验协议 (Cross-Source Verification)

盘点质量的命门。**同一条目至少两个独立来源命中才算"已核实"**。

## 三种来源

1. **台账/统计表**（xlsx）：单位级的权威计数来源。
   - WPS 生成的 xlsx 常让 openpyxl 抛异常（`TypeError: Fill() takes no arguments` 等），
     用 `scripts/robust_xlsx.py` 的 zipfile+XML 兜底解析，不要放弃。
2. **官方名单/公示**（PDF）：获奖名单、立项名单、表彰决定等。
   - 文字版用 pymupdf `page.get_text()`；扫描件转 PNG 后用 rapidocr OCR。
   - OCR 注意：表格多列时文字会被按列打散，核对时用"参赛队名/编号+指导教师"成对匹配。
3. **原始凭证**（证书/合同/通知书）：OCR 核对姓名、奖项、证书编号、日期。

## 核验步骤

```
1. 从台账取候选条目清单（类别+名称+归属人）。
2. 到官方名单中逐条找对应（用编号/队名/姓名匹配）。
3. 抽查关键凭证（获奖等级、登记号、证书编号）与台账一致。
4. 不一致时：记录两条来源的证据路径，标注"矛盾"，交付用户裁决。
5. 用户裁决后：全表统一到该口径。
```

## 常见坑

- 官方名单的"指导教师"与台账可能不一致（同一项目换指导老师）。以证书/官方为准，并提示。
- 获奖名单里同一年度、同一赛事的队伍可能归属不同教师，按指导教师列逐队核对。
- 扫描件 OCR 会漏字/错字（如人名"王小明"误读为"王小月"），人名以台账/单位记录为准。
- 年度口径（学年 vs 自然年）要明确，别混用。

## 核验通过标准

- 每条目都有 ≥2 来源。
- 计数与用户确认口径一致。
- 矛盾清单已交付用户并裁决。
