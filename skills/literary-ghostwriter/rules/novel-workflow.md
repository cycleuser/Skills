# 长篇创作工作流详解 / Long-Form Novel Workflow

SKILL.md 里的长篇流程在这里展开成可执行步骤。一句话概括：**先建库，再规划，后动笔，动笔后回填库。**

---

## 一、四阶段总览

```
建库（新建）→ 规划（规划/章纲）→ 动笔（续写）→ 回填（审稿/更新追踪器）
     ↑                                                    │
     └──────────────── 下一章循环 ←───────────────────────┘
```

| 阶段 | 命令 | 产物 |
|------|------|------|
| 建库 | `/文豪 新建`、`设定`、`人物`、`大纲` | project.yaml、world-building.md、characters/、outline.md |
| 规划 | `/文豪 规划`、`章纲 <N>` | 本章目标、场景序列、伏笔计划、钩子 |
| 动笔 | `/文豪 续写` | chapters/chNNN.md |
| 回填 | `/文豪 审稿`、`伏笔`、`人物` | review-log.md、foreshadowing.md、人物卡状态 |

---

## 二、建库阶段

新建项目时，最小可用集是「一个核心设定 + 三到五张人物卡 + 一份三幕大纲」。
缺了大纲可以先建，但缺了核心设定或人物卡，续写一定会漂。

**风格分配**（可选项，但长篇强烈建议用）：
同一部书里，不同的人或场次可以用不同的作家声部，形成复调。

```
叙述者视角：老舍（市井温度）
男主独白：鲁迅（冷峻自省）
感情线：茨维格（克制深情）
打斗：古龙（极简留白）
权谋：莎士比亚（戏剧冲突）
```

分配写在 project.yaml 的 `style_map` 里，续写时按段调用。

---

## 三、规划阶段

每次动笔前，先过一遍这张单子，答案写进章纲。

1. **位置**：上一章结束在哪儿，人物的物理位置与情绪位置。
2. **目标**：本章必须推动哪条线，必须完成哪一步人物弧线。
3. **出场**：谁必须出场，以谁的视角，他的状态和上次是否接得上。
4. **冲突**：本章的核心冲突是内、外还是人际，如何升级或转折。
5. **伏笔**：本章埋几个、收几个，收的是哪一条。
6. **钩子**：开篇三百字怎么抓人，结尾怎么让人翻页。

章纲模板见 SKILL.md 的「第三步：章纲生成」。

---

## 四、动笔阶段

续写的执行顺序：

1. 载入项目状态、最近一到三章、相关人物卡、待回收伏笔。
2. 若没有章纲，先补一份，请用户过目。
3. 按 `style_map` 决定这一段的声部。
4. 以目标作家的精神内核驱动，而不是套词汇。
5. 写完立刻回填：更新伏笔追踪器、人物卡状态、project.yaml 字数。

**每次只写一章。** 一次写多章会让一致性检查失效。

---

## 五、风格断点

同一风格连写太长会让读者疲劳。每五到八章插一个「风格断点」：
一封信、一首诗、一段日记、一份报纸剪报、另一个人的视角。
断点本身也要符合全书基调，不能突兀。

---

## 六、多人物视角长篇

人物超过五位时，给每个人一张「声线卡」，记录：
口头禅、句长偏好、称呼别人的方式、生气时的话、害怕时的动作。
续写前对照，避免所有人说话一个腔调。

---

## 七、常见问题

| 症状 | 处理 |
|------|------|
| 越写越平 | 用 `/文豪 网文` 检查爽点密度，或加风格断点 |
| 人物漂移 | 回看人物卡，对照审稿，必要时回退章节 |
| 伏笔忘收 | 看伏笔追踪器，逾期条目重新规划回收时机 |
| 时间线混乱 | 用 `/文豪 规划` 重建情节时间线 |
| 断更太久 | 用 `/文豪 规划` 重新加载上下文与人物状态 |
