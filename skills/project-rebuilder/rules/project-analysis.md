# 参考项目分析方法

## 分析目标

分析参考项目的核心特性、技术栈、架构设计，为重建提供依据。

## 分析流程

### 步骤 1：项目概览

```markdown
## 项目概览

**名称**: {project_name}
**URL**: {repo_url}
**Stars**: {stars}
**语言**: {primary_language}
**License**: {license}

**简介**:
{项目描述}

**核心功能**:
- 功能 1
- 功能 2
- 功能 3
```

### 步骤 2：代码结构分析

```markdown
## 代码结构

{project}/
├── src/                    # 源代码
│   ├── core/              # 核心模块
│   ├── api/               # API 层
│   └── utils/             # 工具函数
├── tests/                  # 测试代码
├── docs/                   # 文档
└── config/                 # 配置文件

### 核心模块分析

| 模块 | 文件数 | 代码行数 | 复杂度 | 说明 |
|-----|-------|---------|-------|------|
| core | 15 | 5000 | 高 | 核心业务逻辑 |
| api | 8 | 2000 | 中 | 对外接口 |
| utils | 20 | 3000 | 低 | 工具函数 |
```

### 步骤 3：核心特性提取

```markdown
## 核心特性

### P0 - 必须重建
| 特性 | 描述 | 复杂度 | 依赖 |
|-----|------|-------|-----|
| 特性 A | {描述} | 高 | 无 |
| 特性 B | {描述} | 中 | 特性 A |

### P1 - 应该重建
| 特性 | 描述 | 复杂度 | 依赖 |
|-----|------|-------|-----|
| 特性 C | {描述} | 中 | 特性 A |

### P2 - 可选重建
| 特性 | 描述 | 复杂度 | 依赖 |
|-----|------|-------|-----|
| 特性 D | {描述} | 高 | 特性 B |
```

### 步骤 4：技术栈分析

```markdown
## 技术栈

### 核心技术
- 语言：{language} {version}
- 框架：{framework}
- 关键库：{key_libraries}

### 架构模式
- {pattern}: {description}

### 关键技术决策
| 决策 | 选择 | 理由 |
|-----|------|-----|
| 数据存储 | SQLite | 轻量、嵌入 |
| 通信协议 | HTTP/REST | 通用、简单 |
```

### 步骤 5：核心算法/逻辑分析

```markdown
## 核心算法

### 算法 A

**输入**: {input}
**输出**: {output}
**复杂度**: O(n)

**伪代码**:
```
function algorithm_a(input):
    // 步骤 1
    // 步骤 2
    return result
```

**关键点**:
- 关键点 1
- 关键点 2
```

## 分析工具

### 代码统计

```bash
# 代码行数统计
cloc .

# 依赖分析
pipreqs .  # Python
npm ls     # JavaScript
```

### 架构图生成

```bash
# 生成依赖图
pydeps src/ --show-deps

# 生成调用图
pyan src/*.py --uses --no-defines --colored --grouped --dot > deps.dot
```
