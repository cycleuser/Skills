# 团队并行审查流程

## 审查角色

### 架构师 (Architect)

**审查重点**：
- 技术选型合理性
- 模块划分清晰度
- 扩展性设计
- 架构模式选择

**审查清单**：
- [ ] 技术栈选择是否有充分理由
- [ ] 模块职责是否单一
- [ ] 模块间依赖是否合理
- [ ] 是否有清晰的接口定义
- [ ] 是否考虑了扩展性
- [ ] 是否有单点故障风险

### 开发者 (Developer)

**审查重点**：
- 代码规范一致性
- 功能实现完整性
- 边界情况处理
- 错误处理机制

**审查清单**：
- [ ] 代码风格是否一致
- [ ] 命名是否清晰
- [ ] 函数是否过长（>50 行）
- [ ] 是否有重复代码
- [ ] 错误处理是否完善
- [ ] 边界情况是否考虑

### 测试员 (Tester)

**审查重点**：
- 测试覆盖率
- 边界情况测试
- 集成测试设计
- 测试数据准备

**审查清单**：
- [ ] 核心功能是否有测试
- [ ] 边界情况是否覆盖
- [ ] 是否有集成测试
- [ ] 测试数据是否充分
- [ ] 是否有性能测试
- [ ] 是否有错误场景测试

## 审查流程

```
┌─────────────────────────────────────────────────────────────┐
│                   审查流程                                   │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  代码提交 → 并行审查 → 意见汇总 → 改进清单 → 执行改进        │
│              (3 角色)     (合并)       (优先级)   (ralph)    │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 步骤 1：并行审查

```markdown
## 审查报告 - 迭代 N

### 架构师审查

**审查时间**: {time}
**审查内容**: {content}

**通过项**:
- ✅ {项 1}
- ✅ {项 2}

**改进项**:
- ⚠️ [P0] {改进项 1}
- ⚠️ [P1] {改进项 2}

**备注**:
{额外说明}

---

### 开发者审查

...

---

### 测试员审查

...
```

### 步骤 2：意见汇总

```markdown
## 审查意见汇总

### P0 - 必须改进
| 改进项 | 来源 | 原因 |
|-------|------|-----|
| 增加错误处理 | 开发者 | 核心功能无错误处理 |
| 补充边界测试 | 测试员 | 边界情况未覆盖 |

### P1 - 应该改进
| 改进项 | 来源 | 原因 |
|-------|------|-----|
| 拆分过长函数 | 开发者 | 函数超过 100 行 |
| 增加配置模块 | 架构师 | 硬编码过多 |

### P2 - 建议改进
| 改进项 | 来源 | 原因 |
|-------|------|-----|
| 优化日志格式 | 架构师 | 日志不够结构化 |
```

## 审查会议模板

```markdown
## 审查会议

**时间**: {timestamp}
**参与**: 架构师、开发者、测试员

### 议程

1. 架构师汇报（5min）
2. 开发者汇报（5min）
3. 测试员汇报（5min）
4. 讨论改进项（10min）
5. 确定优先级（5min）

### 决议

**P0 改进项**:
- {项 1} - 负责人：{who} - 截止：{when}
- {项 2} - 负责人：{who} - 截止：{when}

**P1 改进项**:
- {项 1} - 负责人：{who} - 截止：{when}
```

## 审查通过标准

### P0 通过标准（必须满足）

- [ ] 所有 P0 改进项已完成
- [ ] 核心功能测试通过
- [ ] 无严重错误

### P1 通过标准（尽量满足）

- [ ] 80% 以上 P1 改进项完成
- [ ] 代码质量达标
- [ ] 测试覆盖率 >70%

### P2 通过标准（可选）

- [ ] 时间允许则完成
- [ ] 不影响核心功能
