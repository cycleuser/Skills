# 双重 — 对抗式规划 (Adversarial Planning)

## 状态：Beta

## 用途
使用单一模型的5个对抗角色进行3轮交叉批判辩论，生成计划。只有经得起所有攻击的观点才能进入最终计划。适用于需要最大严谨度的复杂项目规划。

## 快速命令
| 命令 | 说明 |
|------|------|
| `/双重 <任务>` | 启动完整对抗式规划（3轮辩论） |
| `/双重 status` | 查看辩论进度 |
| `/双重 plan` | 从存活洞察生成执行计划 |
| `/adversarial <task>` | 英文版命令 |

## 核心创新

### 单模型多角色 vs 多模型多角色

多模型方案使用多个不同模型进行对抗，但引入跨模型通信开销、模型能力不均导致审查偏斜、配置复杂（需要多个API key）等问题。

双重方案使用单一模型切换5个角色prompt：
- 同一个模型通过不同角色prompt切换视角
- 零通信开销——角色输出直接在上下文中
- 配置简单——只需要一个API key
- 但保留了完整的交叉批判审查价值

### 3轮辩论机制

1. **Round 1: 独立分析** — 每个角色独立产出3-7条发现
2. **Round 2: 交叉攻击** — 每个角色攻击其他4个角色的发现
3. **Round 3: 辩护与精炼** — 被攻击角色DEFEND/REFINE/CONCEDE
4. **洞察蒸馏** — 过滤出存活洞察，分类为硬约束/决策/风险/未决问题
5. **生成计划** — 从存活洞察生成可执行任务序列

## 适用场景
- 复杂架构规划 — 需要多视角审查
- 高风险项目 — 需要最大化严谨度
- 创新项目 — 需要打破传统思维
- 跨模块重构 — 需要评估爆炸半径
- 技术选型辩论 — 需要排除选项的明确理由
