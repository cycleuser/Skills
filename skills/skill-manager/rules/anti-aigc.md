# 技能文档反AIGC检测规则

技能管理器产出的文档（技能元数据描述、注册表条目、技能对比分析）面临独特的AIGC风险——技能描述容易被写成"功能强大的综合性工具"这类万能模板。好的技能描述读起来像开发者在30秒电梯里向你解释它干什么的；AI生成的读起来像广告文案，空话连篇。

## 核心原则

技能文档反AIGC的关键是**边界明确**和**不做万能声明**。AI倾向生成"全面/强大/智能"等适用于任何技能的泛泛描述。人类写技能描述会写它能干什么和不能干什么，会写具体的命令和输出，会用数量和限制条件代替形容词。

## 技能文档AIGC高发模式

### 1. 描述使用万能形容词（权重30%）

```
❌ AI模式：
"一个功能强大的综合性技能管理工具"
"提供智能化的技能发现和管理"
"全面支持技能的生命周期管理"
"高效便捷的技能注册与发现机制"

问题：这些描述可以套用在任何工具上，毫无区分度。

✅ 专业写法：
"扫描.skills/目录的SKILL.md文件，提取name/description/commands字段，生成JSON注册表。不支持嵌套技能（子目录深度=1）。注册耗时<50ms（100个技能），查询耗时<1ms。"
```

### 2. 功能列表空洞（权重25%）

```
❌ AI模式：
"支持技能的自动发现、加载、激活、版本管理"
"提供完整的技能生命周期管理"
"智能化的技能依赖解析"

✅ 专业写法：
"自动发现：遍历.skills/*/SKILL.md，提取frontmatter中的name字段作为key。加载：将SKILL.md的完整内容注入会话上下文。版本管理：通过SKILL.md中的version字段比较，版本格式遵循semver。依赖解析：读取requires字段，递归加载依赖技能——当前不支持循环依赖检测（v2计划）。"
```

### 3. 命令说明无具体输出（权重20%）

```
❌ AI模式：
"列出所有可用技能及其描述"
"加载并激活指定技能"
"查看技能的详细帮助信息"

✅ 专业写法：
"/skills → 输出技能表格：name | description | version | commands_count，按name字母排序
/skill academic-writer → 将academic-writer的SKILL.md内容注入会话，输出'技能 academic-writer 已激活（12条命令，380行规则）'
/skill help academic-writer → 输出该技能的命令列表、参数格式、适用场景和限制说明"
```

### 4. 对比分析无结论（权重15%）

```
❌ AI模式：
"两个技能各有优劣"
"可以根据实际需求选择适合的技能"
"建议根据具体场景灵活搭配使用"

✅ 专业写法：
"sleepless vs power-iterate：sleepless不退出循环（while(true)直到完成），power-iterate有预算上限（时间/token）。选sleepless：当你需要'跑完为止不管多久'。选power-iterate：当你需要'最多跑2小时或100K token'。不选sleepless的场景：CI/CD pipeline（需要超时机制）。"
```

### 5. 变更说明无因果（权重10%）

```
❌ AI模式：
"优化了技能加载机制"
"改进了注册表性能"
"增强了对异常情况的处理"

✅ 专业写法：
"技能加载优化：从'每次加载读全文件'改为'只读frontmatter提取metadata'，加载100个技能从1200ms降至50ms（-96%），因为完整内容只在实际激活时才读取。注册表性能：无变化（已是O(1)哈希查找）。异常处理：新增对SKILL.md格式错误的容忍——缺少name字段时跳过该技能并输出警告，而非直接崩溃。"
```

## 技能文档反AIGC五原则

### 1. 描述写边界而非万能声名

不写"全面支持X"，写"支持X（限制：Y），不支持Z"。

### 2. 功能列表配具体行为

不写"自动发现"，写"扫描.skills/*/SKILL.md，提取name字段"。

### 3. 命令说明配具体输出

不写"列出所有技能"，写"输出技能表格：name | description | version"。

### 4. 对比分析给出选择条件

不写"各有优劣"，写"选A当X，选B当Y，不选A当Z"。

### 5. 变更说明写因果

不写"优化了X"，写"从A改为B，效果从C降至D，原因E"。

## AIGC率检测清单

### 内容检测
- [ ] 技能描述是否包含具体行为而非万能形容词？→全是形容词=AI
- [ ] 功能列表是否有具体实现细节？→只有动词堆砌=AI
- [ ] 命令说明是否有输出样例？→无样例=AI
- [ ] 对比分析是否有选择条件？→各打五十大板=AI
- [ ] 变更说明是否有前后对比数据？→无数据=AI

### 语言检测
- [ ] 是否出现"强大/全面/智能/高效/便捷"五字组合？→出现≥3个=AI
- [ ] 是否有可套用于任何技能的描述？→有=AI
- [ ] 是否有明确的不支持/限制声明？→无=AI
- [ ] 功能描述是否可映射到具体代码行为？→不可映射=AI

### AIGC率评分标准

- 0-15%：像开发者的README，准确、有边界、有样例
- 16-30%：合格，有少量可优化项
- 31-50%：需修改，像广告文案而非技术文档
- 51-70%：需重写，空洞无实质
- 71-100%：纯AI模板，万能形容词堆砌
