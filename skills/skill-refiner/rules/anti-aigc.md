# 技能修炼报告反AIGC检测规则

技能修炼产生的文档（评分报告、改进建议、修炼日志）面临独特的AIGC风险——评分和改进建议容易被写成"有所提升"这类万能套话。好的评分报告读起来像质量审计，每个分数有前后对比和具体改动项；AI生成的读起来像绩效评估模板，分数没来历。

## 核心原则

技能修炼报告反AIGC的关键是**分数有来历**和**改进可操作**。AI倾向生成"完整性85分"这种没来历的数字。人类写评分会写"完整性85→88（+3）：新增了rules/anti-aigc.md，补充了3个边界情况"，改进建议会写具体的操作步骤而非"建议进一步完善"。

## 技能修炼报告AIGC高发模式

### 1. 评分无细节（权重25%）

```
❌ AI模式：
"完整性85分，可读性78分"
"技能质量有所提升"
"整体评分80分"

问题：分数没有来历，无法验证也不可操作。

✅ 专业写法：
"完整性85→88（+3）：
- 新增rules/anti-aigc.md（34行），覆盖了3个之前未处理的边界情况
- 补充了SKILL.md的commands部分，从6个命令扩展到12个命令
- 缺失项：/example命令缺少输出样例——标记为下一轮改进项

可读性78→82（+4）：
- 精简SKILL.md从450行到380行（-15.6%），移除了重复的"核心原则"章节（已在rules/中定义）
- 将3段长描述（>100字）改为列表格式
- 缺失项：命令参数说明仍然密集——需要拆分为参数表格

实用性88→88（不变）：
- 所有12个命令可执行（用/bin/bash实际运行验证过）
- 但/example命令输出格式与文档描述不一致——标记为下一轮改进项"
```

### 2. 改进建议不具体（权重25%）

```
❌ AI模式：
"建议进一步完善文档"
"可以优化命令的结构"
"需要提升代码质量"

✅ 专业写法：
"改进建议（3项，按优先级排序）：
1. [P0-阻塞] /example命令缺少输出样例→用户不知道期望输出格式。修复：在SKILL.md的/example命令描述中添加2个输出样例（正常输出和错误输出）。预计：20分钟。
2. [P1-重要] 命令参数说明密集→4个命令的参数说明超过80字/个，不易扫描。修复：将参数说明从段落改为表格（参数|类型|必填|说明）。预计：30分钟。
3. [P2-改进] SKILL.md英文版缺失→当前只有中文版本，英文用户无法使用。修复：创建SKILL.en.md英文版本。预计：2小时（翻译+校对）。"
```

### 3. 修炼日志模糊（权重20%）

```
❌ AI模式：
"本轮修炼专注于提升技能质量"
"对多个方面进行了改进"
"整体质量有所提高"

✅ 专业写法：
"修炼日志（第3轮/共5轮）：
修改文件：3个（SKILL.md, rules/anti-aigc.md, rules/quality.md）
新增文件：1个（rules/anti-aigc.md）
删除文件：0个
变更行数：+156 -89（净增67行）

具体改动：
- SKILL.md：精简"核心原则"章节（450行→380行），移除与rules/重复的内容
- rules/anti-aigc.md：新增34行，覆盖3个边界情况（评分无细节、改进建议不具体、修炼日志模糊）
- rules/quality.md：修正2个过时的命令示例（/skill list→/skills）

本轮新增覆盖的AIGC模式：3个
剩余未覆盖的AIGC模式：2个（配置文件空泛、错误处理模板化）——下轮计划"
```

### 4. 前后对比缺具体项（权重15%）

```
❌ AI模式：
"经过修炼，技能在多个维度上得到了提升"
"改进前后的差异明显"

✅ 专业写法：
"修炼前后对比：
| 维度 | 修炼前 | 修炼后 | 变化 | 详情 |
|------|--------|--------|------|------|
| 完整性 | 85 | 88 | +3 | 新增anti-aigc.md，补充3个边界 |
| 可读性 | 78 | 82 | +4 | SKILL.md精简15.6%，长描述改列表 |
| 实用性 | 88 | 88 | 0 | 命令可执行但/example输出不一致 |
| 合规性 | 92 | 95 | +3 | 修正2个过时命令示例 |
| 总分 | 341/400 | 353/400 | +12 | +2.8% |

未改进项（2个）：/example输出格式不一致、英文版缺失。"
```

### 5. 下轮计划空泛（权重15%）

```
❌ AI模式：
"下轮将继续优化技能"
"重点关注薄弱环节"
"持续改进质量"

✅ 专业写法：
"下轮修炼计划（第4轮）：
目标：将总分从353提升到360（+7），重点改进实用性维度（88→92）。

具体任务（3项）：
1. 修复/example命令输出格式不一致（预计+2分实用性，20分钟）
2. 创建SKILL.en.md英文版本（预计+3分完整性，2小时）
3. 补充2个未覆盖的AIGC模式到anti-aigc.md（配置文件空泛、错误处理模板化）（预计+2分完整性，30分钟）

不做的事：不修改rules/quality.md的评分算法（已稳定运行3轮，改动风险>收益）。"
```

## 技能修炼报告反AIGC五原则

### 1. 分数配具体改动项

不写"完整性85分"，写"完整性85→88（+3）：新增anti-aigc.md，补充3个边界"。

### 2. 改进建议按优先级排序配操作步骤

不写"建议完善文档"，写"[P0] /example缺输出样例，修复：添加2个输出样例，预计20分钟"。

### 3. 修炼日志量化改动

不写"进行了改进"，写"修改3个文件，+156-89行，精简SKILL.md 15.6%"。

### 4. 前后对比用数据表格

不写"差异明显"，写"完整性85→88（+3），可读性78→82（+4），实用性88→88（不变）"。

### 5. 下轮计划具体到任务和时间

不写"继续优化"，写"3项任务：修复/example（20min）、英文版（2h）、2个AIGC模式（30min）"。

## AIGC率检测清单

### 内容检测
- [ ] 分数是否有具体改动项列表？→光有分数=AI
- [ ] 改进建议是否有P0/P1/P2优先级和操作步骤？→笼统建议=AI
- [ ] 修炼日志是否有具体的文件列表和行数统计？→泛泛而谈=AI
- [ ] 前后对比是否有数据表格？→无表格=AI
- [ ] 下轮计划是否具体到任务和时间？→"继续优化"=AI

### 语言检测
- [ ] 是否出现"有所提升/进一步完善/持续改进"等万能套话？→大量出现=AI
- [ ] 分数是否有前后对比（X→Y）和具体改动项？→只有单点分数=AI
- [ ] 改进建议是否有"不做的事"？→全是待改进=AI
- [ ] 日志是否列出了具体文件名？→无=AI

### AIGC率评分标准

- 0-15%：像质量审计报告，每分有来历、每项可操作
- 16-30%：合格，有少量可优化项
- 31-50%：需修改，分数没来历、建议不具体
- 51-70%：需重写，像绩效评估模板
- 71-100%：纯AI模板，万能套话堆砌
