# 改进策略

## 改进原则

1. **最小改动原则**: 优先选择改动最小、效果最好的方案
2. **渐进式改进**: 分步骤改进，每步验证
3. **保留核心**: 改进不改变技能的核心功能
4. **向后兼容**: 改进不破坏现有用法

---

## 改进策略库

### 策略：完整性改进

#### 问题：SKILL.md 缺少必要字段

```yaml
问题: YAML frontmatter 不完整
影响: 技能无法被正确加载
方案:
  1. 添加缺失字段
  2. 确保字段值有效
优先级: 高

示例:
  修复前:
  ---
  name: my-skill
  ---

  修复后:
  ---
  name: my-skill
  version: "1.0.0"
  description: |
    技能描述
  author: author-name
  license: MIT
  ---
```

#### 问题：规则文件缺失

```yaml
问题: rules 字段列出的文件不存在
影响: 规则无法被加载
方案:
  1. 创建缺失的规则文件
  2. 或从 rules 字段中移除
优先级: 高
```

### 策略：可读性改进

#### 问题：文档结构混乱

```yaml
问题: 标题层级不合理，无目录结构
影响: 难以查找信息
方案:
  1. 重新组织标题层级
  2. 添加清晰的目录
  3. 使用一致的章节命名
优先级: 中

改进模板:
  # 技能名称

  ## Quick Commands
  ## 概述
  ## 功能详解
  ## 使用示例
  ## 配置选项
  ## Rules
```

#### 问题：文档过长

```yaml
问题: SKILL.md 内容过多，重点不突出
影响: 用户难以快速理解
方案:
  1. 提取核心内容，精简 SKILL.md
  2. 详细内容移至规则文件
  3. 保留关键信息和示例
优先级: 中

精简原则:
  - 保留：功能描述、命令列表、快速示例
  - 移动：详细规则、长篇示例、边缘情况
  - 删除：重复内容、过时信息
```

#### 问题：示例缺失或不足

```yaml
问题: 缺少使用示例
影响: 用户不知道如何使用
方案:
  1. 添加基础用法示例
  2. 添加进阶用法示例
  3. 添加常见场景示例
优先级: 中

示例模板:
  ## 使用示例

  ### 基础用法

  ```
  /命令 参数
  ```

  ### 进阶用法

  ```
  /命令 参数 --选项 值
  ```

  ### 常见场景

  **场景1**: {描述}
  ```
  {示例命令}
  ```
```

### 策略：实用性改进

#### 问题：规则不够具体

```yaml
问题: 规则描述抽象，难以执行
影响: 技能行为不可预测
方案:
  1. 将抽象规则具体化
  2. 添加可执行的步骤
  3. 添加判断标准
优先级: 高

改进示例:
  修复前:
  - 保持代码简洁

  修复后:
  - 函数长度不超过50行
  - 嵌套层级不超过3层
  - 删除未使用的导入
```

#### 问题：缺少错误处理

```yaml
问题: 无错误处理指导
影响: 遇到问题无法处理
方案:
  1. 列出常见错误
  2. 提供错误处理方法
  3. 添加调试建议
优先级: 中

改进模板:
  ## 常见问题

  ### 问题1：{描述}
  **原因**: {原因}
  **解决**: {方法}

  ### 问题2：{描述}
  **原因**: {原因}
  **解决**: {方法}
```

### 策略：一致性改进

#### 问题：命名风格不统一

```yaml
问题: 文件/变量命名风格混乱
影响: 可读性差，维护困难
方案:
  1. 统一使用小写+连字符
  2. 批量重命名文件
  3. 更新引用
优先级: 中

命名规范:
  技能名: skill-name (小写、连字符)
  规则文件: rule-name.md
  命令文件: command-name.md
```

#### 问题：格式风格不统一

```yaml
问题: 代码块、列表、表格格式不一致
影响: 视觉效果差
方案:
  1. 制定格式规范
  2. 批量格式化
  3. 检查验证
优先级: 低
```

---

### 策略：可扩展性改进

#### 问题：规则不够模块化

```yaml
问题: 规则耦合度高，难以扩展
影响: 添加新功能困难
方案:
  1. 拆分大规则为小规则
  2. 定义清晰的规则接口
  3. 添加规则组合机制
优先级: 中
```

#### 问题：缺少配置选项

```yaml
问题: 无法自定义配置
影响: 灵活性不足
方案:
  1. 识别可配置项
  2. 添加配置选项
  3. 设置合理默认值
优先级: 低

配置模板:
  ## 配置选项

  | 参数 | 默认值 | 说明 |
  |------|--------|------|
  | option1 | default1 | 说明1 |
  | option2 | default2 | 说明2 |
```

## 改进优先级

| 优先级 | 类型 | 说明 |
|-------|------|------|
| 高 | 功能性缺陷 | 影响技能正常使用 |
| 高 | 完整性缺陷 | 缺少必要组成部分 |
| 中 | 可读性问题 | 影响理解和使用 |
| 中 | 一致性问题 | 影响维护和扩展 |
| 低 | 格式问题 | 仅影响美观 |
| 低 | 优化问题 | 可改进但非必须 |

---

## 改进执行流程

```
1. 确定改进范围
   ↓
2. 制定改进计划
   ↓
3. 备份原文件
   ↓
4. 执行改进
   ↓
5. 验证改进效果
   ↓
6. 更新文档
   ↓
7. 生成改进报告
```

---

## 批量改进

当需要改进多个技能时：

```yaml
批量改进流程:
  1. 扫描所有技能
  2. 生成诊断报告
  3. 按优先级排序
  4. 批量执行改进
  5. 生成汇总报告

注意事项:
  - 保持技能间的一致性
  - 避免重复改进
  - 记录所有修改
```
