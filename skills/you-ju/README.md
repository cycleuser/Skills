# 有据 (Grounded Generation)

## 状态：Beta

## 用途

防幻觉的严格转述技能。在知识库检索、网页搜索、文档整合的每一步生成中，执行"闭世界"约束：输出中的每个实体、数字、因果关系必须能在给定来源中找到对应，禁止新增实体、新增数字、新增逻辑关系。幻觉不是靠"小心"避免的，是靠**每步审计 + 无据即删**的机制避免的。

## 快速命令

| 命令 | 说明 |
|------|------|
| `/有据 <任务>` | 严格有据模式执行检索/整合/转述 |
| `/有据 审计 <输出> [来源目录]` | 对已有输出做幻觉审计 |
| `/有据 对照 <输出> <来源>` | 逐句对齐，标注无据句 |
| `/有据 实验` | 运行基线 vs 受控对照实验 |
| `/grounded <task>` | English workflow |
| `/grounded audit <output>` | Audit existing output |

## 解决什么问题

模型做检索增强生成时的三类典型幻觉：

1. **实体增加**（E1）：补出语料外的机构/人名/产品名——"星尘-3 采用**台积电** 12nm 工艺"
2. **数字增加**（N1）：语料没给的数值"补全"一个典型值——"FP16 算力**约 4 TOPS**"
3. **逻辑关系增加**（R1）：来源只并列陈述，输出写成因果/比较——"因此能效领先"

以及最高频的 **Q1 越权回答**：来源明说"未提供"，输出仍给了答案。

## 工作机制

```
闭世界约束（来源没提的事 = 不存在）
  ↓
三步一审计（检索后 / 每段生成后 / 交付前）
  ↓
句级引用标记 [A:L12]，脚本逐条回查
  ↓
违规句 3 轮降级：删改 → "来源未提及" → 引号原文摘录
  ↓
交付时附"来源未覆盖"清单
```

## 实测效果（A/B 对照，虚构语料）

同一组源文档，同样任务提示，无约束生成 vs 按本技能协议生成：

| 任务 | 组 | E1 实体泄漏 | N1 数字泄漏 | 句级有据率 |
|------|----|------------|------------|-----------|
| T1 摘要 | baseline | 14 | 1 | 50% |
| T1 摘要 | **grounded** | **0** | **0** | **100%** |
| T2 FAQ | baseline | 11 | 7 | 50% |
| T2 FAQ | **grounded** | **0** | **0** | **100%** |
| T3 竞品对比 | baseline | 16 | 9 | 40% |
| T3 竞品对比 | **grounded** | **0** | **0** | **100%** |

baseline 的典型泄漏：编造"台积电/NPU/LPDDR4/PyTorch/TensorFlow/Jetson Nano"等实体、编造"16 TOPS/1999 元/2 GB/73%/15% 份额"等数字、对"未提供"问题越权作答。grounded 组在同样诱因下全部转为"来源未提及"或显式缺口声明。

完整报告见仓库 `test/you-ju.md`。

## 关键设计：为什么用虚构语料测试

现实语料无法精确判定幻觉（不知道输出实体是不是真实存在）。虚构语料（"星尘-3"芯片）是闭集：白名单 = 语料实体全集，输出中任何白名单之外的实体**必然**是编造——幻觉计数从估计变成精确计数。

## 校验脚本

`scripts/ground_check.py`（只读）：

```bash
python3 ground_check.py whitelist <来源...> -o wl.json   # 建白名单
python3 ground_check.py check <输出.md> --whitelist wl.json --sources <来源...>  # E1/N1/C1/Q1
python3 ground_check.py align <输出.md> <来源...>         # 句级有据率
python3 ground_check.py coverage <输出.md> <来源...>      # 来源要点覆盖率
```

机械可判定：E1（实体）、N1（数字）、C1（引用失配）。
需模型自审：R1（关系增加）、Q1（越权回答）——审计协议中为必需步骤。

## 局限（如实说）

- 中文无分词词典，实体判定用"白名单 + 字级 + 3-gram 命中 + 功能词表"四层启发式，少量元话语残段会进报告（标注 kind=cn，人工复核即可）；英文实体判定精准
- R1/Q1 无法脚本化，依赖模型自审；自审漏检时无兜底
- 单轮生成 ≠ 协议完整执行；3 轮修复循环是协议的一部分
- 换 LLM 底座需重跑对照实验
