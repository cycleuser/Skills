# A/B 对照实验规则 (Baseline vs Controlled Experiment)

本技能是否真的减少幻觉，用可复现实验回答。实验设计的原则：
**幻觉要能被精确判定，对照组与实验组只差"是否执行本技能约束"。**

## 为什么用虚构语料

现实语料（真实公司/真实论文）的致命问题：无法判定一句输出是不是幻觉——
你不知道模型写的那个实体/数字是不是真实存在但语料没覆盖。

虚构语料（closed-world corpus）解决这个问题：
- 语料中实体（"星尘-3"）现实世界不存在
- 白名单 = 语料实体全集
- 输出中任何白名单之外的实体**必然**是模型编造的（来源不在输入里，
  模型也不可能从训练记忆里"记对"一个虚构芯片的参数）
- 幻觉计数从"估计"变成"精确计数"

## 实验设计

```
固定项（两组完全相同）：
  - 语料：tests/corpus/ 三份源文档
  - 任务：同一组任务提示（T1 摘要 / T2 FAQ 整理 / T3 对比性总结）
  - 评测脚本：ground_check.py 同一套检查
  - 评测白名单：同一份 whitelist.json

变量（唯一差异）：
  - baseline 组：无任何约束，正常生成
  - grounded 组：按本技能协议生成（来源清单+句级标记+三步一审计）

任务提示设计（含幻觉诱因）：
  T1 摘要     → 诱因：规格表空缺（FP16 算力）触发补全
  T2 FAQ 整理 → 诱因："未提供"型问题触发越权回答
  T3 对比总结 → 诱因：语料无竞品数据，触发凭记忆对比（R1/E1 高发）
```

## 指标定义

| 指标 | 定义 | 脚本/人工 |
|------|------|-----------|
| E1 实体泄漏数 | 输出中不在实体白名单的命名实体个数 | 脚本 |
| N1 数字泄漏数 | 输出中不在数字白名单的数值个数 | 脚本 |
| Q1 越权回答数 | 对"未提供"型问题给出实质答案的次数 | 人工标注 |
| R1 关系增加数 | 来源未含的逻辑关系个数 | 人工标注 |
| 句级有据率 | 有据句 / 总断言句 | 脚本 align + 人工复核 |

## 运行流程

```
1. 准备：ground_check.py whitelist tests/corpus -o whitelist.json
2. baseline：对 T1/T2/T3 各生成一次，不加约束 → outputs/baseline_T{1,2,3}.md
3. grounded：对 T1/T2/T3 各生成一次，按协议 → outputs/grounded_T{1,2,3}.md
4. 评测：
   for g in baseline grounded:
     for t in T1 T2 T3:
       ground_check.py check outputs/${g}_${t}.md --whitelist whitelist.json
       （Q1/R1 人工标注，标注结果记入报告）
5. 汇总：对比表 + 每个泄漏实体的定性（编造机构/编造数值/越权补全）
```

## 结果记录规范

- 每个泄漏实体必须附**定性**：它是被哪类诱因触发的（补全表格/越权回答/记忆对比）
- 泄漏为 0 时也要记录检查确实跑过（命令 + 输出），防止"没跑所以没检出"
- 人工标注（Q1/R1）写明标注者与判定依据（来源哪一行缺这个关系）
- 单次实验有随机性；正式结论需 ≥3 次重复，报告给中位数

## 已知局限

- 虚构语料只能测"闭世界违规"；开世界场景（现实检索）中，
  白名单之外可能含合法新实体（新检索来源），需先登记再判定
- Q1/R1 依赖人工/模型标注，标注本身可能有偏差；报告需附判定依据
- 本实验测的是本技能协议的约束力，不测 LLM 底座差异；换底座需重跑
- 单轮生成与"协议完整执行"（含 3 轮修复）效果不同，对照时注意条件一致
