# 审计协议 (Audit Protocol)

三步一审计：检索后、每次生成后、交付前。审计是机制不是态度——靠流程兜底，不靠"小心"。

## 审计时点总览

```
检索后审计（A1）→ 防止引用计划建立在无据断言上
生成后审计（A2）→ 每完成一段/一次生成即跑，防违规累积
交付前审计（A3）→ 全量重跑 + 覆盖检查 + 未覆盖清单
```

只跑 A3 不跑 A2 是反模式：违规累积到最后才发现，重写成本高，
且"多轮重写"本身会引入新违规（见 A2 的轮次记录要求）。

## A1 检索后审计

**时点**：来源清单建立后、动笔前。

检查项：
- [ ] 每个来源已登记编号（A/B/C…），编号在输出中稳定使用
- [ ] 每条计划引用的断言，都能在来源中定位到具体行
      （定位不到的断言，从引用计划中删除，或先补检索）
- [ ] 白名单已生成：`ground_check.py whitelist <来源目录> -o whitelist.json`
- [ ] 用户问题清单中，哪些子问题语料能答、哪些不能——不能答的先标记，
      预写"来源未提及"回答，防止生成时手滑补全

## A2 生成后审计（每段）

**时点**：每完成一段生成（或每次工具调用返回后）。

检查项（脚本 + 自审）：
- [ ] `ground_check.py check <输出> --whitelist ... --sources ...` 通过
- [ ] 每个断言句有引用标记，标记回查通过（C1 = 0）
- [ ] 自审连接词/比较结构：R1 = 0
- [ ] 自审"未提供"处理：来源显式说未提供的问题，输出是否也说了未提供（Q1 = 0）

违规处理轮次记录（必须留痕）：
```
轮次 1：检出违规句 → 删除违规成分重写 → 重跑 check
轮次 2：仍违规 → 整句降级为"来源未提及 X"或引号摘录 → 重跑 check
轮次 3：仍违规 → 该句所在断言整段移除，进"来源未覆盖"清单
上限 3 轮；轮次记录写入交付汇报（检出什么、怎么处理的）
```

注意：**每轮重写后必须重跑全量 check**，不是只查改过的句——
重写本身会引入新实体/新数字。

## A3 交付前审计

**时点**：输出定稿后、汇报前。

检查项：
- [ ] 全量 `ground_check.py check` 全绿（E1=0, N1=0, C1=0）
- [ ] R1/Q1 自审通过（这两类脚本测不了，模型必须显式过一遍检查单）
- [ ] 引用标记密度合理：无"大引用刷白"（单标记 > 5 行）
- [ ] "来源未覆盖"清单已附：本次用户问题中语料答不了的部分逐条列出
- [ ] 汇报顺序正确：结论 → 来源清单 → 审计结果（含修复轮次记录）→ 未覆盖清单

## 审计报告格式

```markdown
## 有据审计报告 / Grounded Audit Report

**输出文件**: summary.md
**来源清单**: A=source_A.md, B=source_B.md, C=source_C.md
**审计时间**: 2026-09-12T10:30:00+08:00
**模式**: strict（无据即删）

### 脚本检查结果

| 检查项 | 结果 | 明细 |
|--------|------|------|
| E1 实体泄漏 | ✅ 0 | — |
| N1 数字泄漏 | ❌ 1 | 第5句 "4 TOPS" 不在数字白名单 |
| C1 引用失配 | ❌ 1 | 第7句 [A:L12] 指向功耗行，断言为算力 |
| 覆盖率（可选） | 6/9 要点 | 未覆盖：散热、量产、封装 |

### 模型自审结果

| 检查项 | 结果 | 明细 |
|--------|------|------|
| R1 关系增加 | ✅ 0 | 逐句过连接词检查单 |
| Q1 越权回答 | ✅ 0 | FP16/级联/套件三问均答"来源未提及" |

### 修复轮次记录

| 轮次 | 检出 | 处理 | 复查 |
|------|------|------|------|
| 1 | N1×1（第5句） | 删除猜测值，改"来源未提及" | check 通过 |
| 2 | C1×1（第7句） | 修正标记为 [A:L17] | check 通过 |

### 来源未覆盖清单

- FP16 算力（源 C Q4 明示未给出）
- 价格/客户/良率（三份源文档均未涉及）
```

## 对已有输出的事后审计（/有据 审计）

输入是"输出 + 来源"，流程：

1. 从来源建白名单
2. 跑 `ground_check.py check` 得 E1/N1/C1 机械结果
3. 对无引用标记的输出：先跑 `ground_check.py align` 逐句对齐，
   无据句列表交模型判 R1/Q1
4. 输出审计报告（格式同上），每条违规附**证据**：白名单缺失证明、
   来源行内容 vs 输出断言的对比
5. 不自动改写输出——审计报告给出修复建议，改不改由用户决定

## 审计的失败模式

| 失败模式 | 后果 | 对策 |
|----------|------|------|
| 白名单过宽（把整段原文灌进去） | 检查形同虚设 | 白名单是实体/数字级，不是句子级 |
| 只跑脚本不跑自审 | R1/Q1 全漏 | 模型自审是协议必需步，不是可选项 |
| 重写后不重跑全量 | 新违规漏网 | 每轮全量重跑，见 A2 |
| 审计通过但引用标记是后补的 | 标记与断言脱节 | 标记必须生成时同步写，后补按 C1 全查 |
