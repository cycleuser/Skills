# 自治迭代报告反AIGC检测规则

自控迭代产生的文档（决策日志、状态报告、迭代总结）面临独特的AIGC风险——自治迭代强调自动决策，容易出现只有结论没有推理过程的记录。好的决策日志读起来像工程师写的rationale文档，每个选择都有约束和排除理由；AI生成的读起来像会议纪要，只有"讨论了X，决定了Y"。

## 核心原则

自治迭代报告反AIGC的关键是**推理可追溯**和**预算透明**。AI倾向生成"选择了最优方案"的结论式记录。人类写决策日志会写"为什么选这个而非那个"，会标注[自决]标记（用户未指定），会写预算消耗的前后对比。

## 自治迭代报告AIGC高发模式

### 1. 决策记录空洞（权重30%）

```
❌ AI模式：
"选择了JWT方案"
"预算使用合理"
"根据实际情况调整了方案"

✅ 专业写法：
"决策ID:2 选择JWT而非Session——理由：(1)本系统是分布式API，Session需要Redis共享状态（增加1个依赖和0.5天配置）；(2)移动端无Cookie概念，JWT更适合；(3)JWT可携带用户角色信息减少数据库查询（从每次请求2次降为0次）。折衷：JWT无法主动失效，需配合黑名单（额外1天开发）。标记[自决]——用户未指定，JWT更现代更主流。预算消耗：预估2天→实际2.5天（+25%），超出的0.5天花在JWT刷新token的竞态条件调试上。"
```

### 2. 状态报告模糊（权重25%）

```
❌ AI模式：
"当前进展顺利"
"整体状态良好"
"已完成了主要工作"
"遇到的问题已经解决"

✅ 专业写法：
"状态报告（迭代#4/共8轮）：
| 维度 | 状态 | 前值 | 变化 |
|------|------|------|------|
| 测试覆盖率 | 74% | 68% | +6% |
| ruff errors | 8 | 23 | -65% |
| API p50延迟 | 52ms | 120ms | -57% |
| 未解决bug | 1 | 5 | -80% |
| 预算消耗 | 45% | 30% | +15pp |

瓶颈：gui模块PySide6 WebEngine加载超时（3.2s vs 目标2s），根因是Qt初始化开销无法优化——考虑降级为QML方案（需要0.5天重写）。"
```

### 3. 预算不透明（权重20%）

```
❌ AI模式：
"预算使用在合理范围内"
"资源消耗可控"
"迭代成本适中"

✅ 专业写法：
"预算消耗明细：
- Token使用：387K/800K（48.4%）——其中LLM调用320K，工具调用67K
- 时间消耗：3.8小时/8小时预算（47.5%）——其中编码2.1h，测试0.9h，自愈0.5h，回退0.3h
- 迭代效率：有效工作时间3.0h / 总时间3.8h = 79%（21%用于自愈和回退）

预算预测：按当前速率，8轮迭代预计消耗Token 620K（77.5%）和时间7.0h（87.5%）。风险：若gui模块需要重写（+2天），时间预算将超限。建议：提前评估gui降级方案。"
```

### 4. 选择路径无排除（权重15%）

```
❌ AI模式：
"采用了更优的实现方案"
"选择了合适的工具链"

✅ 专业写法：
"选择路径#3: pytest而非unittest——排除理由：
(1) unittest需要继承TestCase类（增加3行样板代码/测试类），pytest只需函数
(2) pytest的fixture机制比unittest的setUp/tearDown更灵活（支持scope=session和fixture依赖）
(3) pytest的参数化测试（@pytest.mark.parametrize）比unittest的subTest可读性好
排除的方案：nose2（已停止维护，最后release 2020年），hy_test（内部框架，无社区支持）

标记[自决]——用户未指定测试框架。"
```

### 5. 迭代总结无量化（权重10%）

```
❌ AI模式：
"经过多轮迭代，代码质量显著提升"
"项目已经达到预期目标"
"整体改进效果明显"

✅ 专业写法：
"8轮迭代总结：
达标项（4/5）：测试覆盖率 62%→89%（+27%达标），ruff errors 34→0（达标），API延迟 120ms→45ms（达标），代码行数 2800→2100（-25%达标）
未达标项（1/5）：GUI启动时间 2.8s vs 目标2s（差40%，根因PySide6 WebEngine）
遗留问题（2项）：(1)并发>500内存泄漏（每小时50MB）；(2)Windows路径分隔符硬编码（仅用/而非os.sep）
总耗时：8天 vs 预算6天（+33%），超时原因：gui模块重写耗时4天（预估2天）。"
```

## 自治迭代报告反AIGC五原则

### 1. 每个决策标注排除理由和[自决]标记

不写"选择X方案"，写"选X而非Y因为Z。标记[自决]"。

### 2. 状态报告用数据表格而非文字描述

不写"进展顺利"，写"覆盖率74%→89%，ruff 23→0"。

### 3. 预算明细到token级别和时间分布

不写"预算合理"，写"Token 387K/800K（48.4%），时间3.8h/8h（47.5%）"。

### 4. 选择路径列出排除的方案

不写"采用了更优方案"，写"选A排除B/C/D，理由：[具体]，排除理由：[具体]"。

### 5. 迭代总结包含量化达标/未达标

不写"显著提升"，写"达标4/5，未达标1/5（列出具体项和差距）"。

## AIGC率检测清单

### 内容检测
- [ ] 每个决策是否有排除理由和[自决]标记？→无理由=AI
- [ ] 状态报告是否有数据表格？→无表格=AI
- [ ] 预算是否细分到token和时间？→只有总预算=AI
- [ ] 选择路径是否列出排除的方案？→只写选择=AI
- [ ] 迭代总结是否有达标/未达标分类？→全是达标=AI

### 语言检测
- [ ] 是否出现"合理/顺利/适当/显著"等模糊修饰？→大量出现=AI
- [ ] 是否有前后对比数据（X%→Y%）？→无=AI
- [ ] 决策是否标注了用户指定vs自决？→无标记=AI
- [ ] 预算数字是否有来源？→无来源=AI

### AIGC率评分标准

- 0-15%：像工程师的rationale文档，推理可追溯、数据透明
- 16-30%：合格，有少量可优化项
- 31-50%：需修改，决策像会议纪要只有结论
- 51-70%：需重写，空洞叙事无实质
- 71-100%：纯AI模板，平滑叙事隐去所有取舍
